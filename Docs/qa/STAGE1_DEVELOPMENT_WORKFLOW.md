# 审查后第一阶段开发工作流

日期：2026-10-12（America/Los_Angeles）。依据五份调研报告的只读审查，以及 V0.2 产品重规划。本文件是本轮 goal 的执行范围，不代表五份报告的建议全部获准实施。

## 范围与顺序

1. 保留现有 build 150 未发布改动，先运行完整回归建立基线。
2. 对能复现的旧歌滞留、活动抢占问题补失败回归，再修改实现。
3. 从 main.swift 提取纯活动与音乐展示策略；不搬动媒体控制、窗口、歌词来源或权限代码。
4. 将音乐到达、提醒排队与提醒后恢复接入同一活动仲裁策略。
5. 完成 Swift 回归、控制安全检查、Release 编译和差异核验，记录验收边界。

本轮不增加音乐源、AI、系统 HUD、剪贴板历史或 Shelf，不替换安装版，不推送或发布。后续独立能力优先评估文件 Shelf；活动源协议待真实迁移需求出现时再引入，不预先复制竞品的完整架构。

## 行为契约

| 场景 | 预期 |
| --- | --- |
| 同来源新歌或同名不同歌手，缺少时间轴 | 不以进度保护保留旧歌及旧歌词；候选可信度仍由现有适配器门禁决定 |
| 同曲短暂缺少时间轴 | 保留可信时间轴，同时更新控制能力及播放状态是否已知 |
| 用户展开活动中心后音乐首次到达 | 保留活动中心；用户仍可主动进入音乐 |
| 正在 seek、拖动或等待播放/切歌回读 | 提醒排队；显式展示也不越过操作保护 |
| 无在途操作且有紧急提醒 | 可接管展开内容，结束后恢复仍有效的原活动 |
| 提醒打断用户展开的活动中心 | 即使音乐出现，仍恢复该活动中心 |
| 运行中计时器被提醒打断 | 仍恢复运行中的计时器；结束计时器不作为运行活动恢复 |

不改变 PID 定向语义控制、不自动拉起或取消最小化汽水、不发送全局媒体键、不放宽歌词同曲核验、不新增媒体轮询、不设置整窗鼠标穿透。

## 验收层次

代码测试与 Release 编译仅证明策略和编译层。目标歌曲前奏署名、物理键盘切歌延迟、前后台实际控制、全屏抑制、像素与命中区，需要候选安装版的独立实机记录；不得沿用旧版本证据宣布本轮通过。

本轮结果见 [第一阶段验收记录](../acceptance/2026-10-12-stage1-activity-policy.md)。目标歌曲署名及键盘延迟仍参考 [build 150 未完成项](../acceptance/2026-10-08-build150-intro-credits-and-publication.md)。

## 后续阶段的进入条件

- 核实本轮活动切换在实机中符合上述契约，再按职责逐步拆分 IslandModel 的事件生命周期；保持取消、代次和回归契约。
- 歌词问题先区分源歌词未暴露、源身份未核验、上游延迟和 UI 发布延迟，再决定修复。没有当前有效样本时不猜原因或增加轮询。
- 独立功能先确定一项具体用户工作流及权限范围，再做可操作原型。签名、公证与更新机制另立发布门禁。

## 2026-10-13 用户调整后的顺序

用户已解锁，明确要求先开发功能、减少测试，并选择“音乐交互：展开方式与歌词显示切换”。先安装已完成代码回归的播放等待修复build179，再开发音乐展开方式与面板内歌词切换build180；不进入Shelf、不新增媒体来源、不推送发布。只进行一次必要回归、Release安装校验和新功能短检查。第三轮快速切歌/音频/物理键盘及长期性能门禁保留未完成，停止反复锁屏预检和长时间观察。详见[音乐交互记录](../acceptance/2026-10-13-build180-music-interaction.md)。

# V0.2 开发计划

## 版本目标

V0.2 的目标是把当前三音乐来源原型推进为“稳定的日常试用版本”：冻结新增应用适配，集中优化悬停动画、主线程性能、状态一致性、设置和长时间运行质量。计时器和通知扩展继续延期。

## 版本原则

- 先稳定，再扩展。
- 不伪造状态，不用错误来源覆盖真实来源。
- 控制命令不能误控视频播放器。
- 主界面保持苹果风格，不显示调试文案。
- 诊断信息放在设置或 CLI 中。

## Milestone 1：MVP 验收封版

时间建议：0.5-1 天

任务：
- 跑完 `Docs/MVP_ACCEPTANCE.md` 的 P0 验收。
- 记录失败项到 `Docs/ISSUE_BOARD.md`。
- 对进度、封面、切歌、视频冲突做 1 轮手动录像验证。

交付物：
- MVP v0.1 验收结论。
- 可复现问题清单。
- 当前版本是否可作为日常试用版的判断。

## Milestone 2：P0 性能与动画优化

时间建议：1-2 天

任务：
- 合并高频鼠标移动事件，避免每个事件创建主线程任务。
- 审计窗口形变、内容动效、封面解码和状态发布的帧节奏。
- 建立空闲、悬停和连续切歌场景的 CPU、内存及响应基线。

验收：
- 悬停开始展开不超过 120ms，连续进出不积压。
- 展开和收回期间只有一个窗口，顶部与中心不漂移。
- 自动化、Release 构建与实机动画回归全部通过。

## Milestone 3：音乐体验稳定性

时间建议：1-2 天

任务：
- 切歌时歌名、歌手、封面做原子更新，避免错位。
- 封面缓存策略升级，避免旧封面残留。
- 进度条继续校准 UI 层，必要时增加临时调试 overlay。
- 验证汽水语义 AX 控件识别的启动开销、失败反馈和系统版本兼容性。

验收：
- 连续切歌 10 次无长期错位。
- 进度条点击展开不回到 0 或几秒。
- 抖音/浏览器视频冲突时不误控视频。

## Milestone 4：设置与长期运行质量

时间建议：2-3 天

任务：
- 补齐开机启动、显示灵动岛、重置布局和权限恢复入口。
- 验证内置屏与外接屏运行时切换。
- 进行 2 小时长时间播放、频繁切歌和来源切换回归。

验收：
- 设置修改立即生效，主岛不出现诊断文案。
- 三个现有来源不会互相覆盖快照或把控制发送给错误应用。
- CPU、内存、线程和状态流子进程无持续增长。

## 暂不进入 V0.2 的事项

- 通知中心完整聚合。
- 会议摄像头/麦克风状态。
- 计时器正式化。
- App Store 发布与公证。
- 真正无感的汽水内部 IPC 控制；该项继续作为架构研究线。
- QQ 音乐、Spotify 及其他新增音乐应用适配。

## 推荐执行顺序

1. 跑 MVP 验收。
2. 修 P0 失败项。
3. 完成现有三来源状态一致性回归。
4. 做设置面板产品化和多显示器回归。
5. 完成长时间运行测试后再评估下一阶段。

# V0.2 开发计划

## 版本目标

V0.2 的目标是把当前可用原型推进为“日常可试用版本”：稳定音乐岛体验，补齐设置面板，明确控制策略，并为计时器功能打基础。

## 版本原则

- 先稳定，再扩展。
- 不伪造状态，不用错误来源覆盖真实来源。
- 控制命令不能误控视频播放器。
- 主界面保持苹果风格，不显示调试文案。
- 诊断信息放在设置或 CLI 中。

## Milestone 1：MVP 验收封版

时间建议：0.5-1 天

任务：
- 跑完 `Docs/MVP_ACCEPTANCE.md` 的 P0 验收。
- 记录失败项到 `Docs/ISSUE_BOARD.md`。
- 对进度、封面、切歌、视频冲突做 1 轮手动录像验证。

交付物：
- MVP v0.1 验收结论。
- 可复现问题清单。
- 当前版本是否可作为日常试用版的判断。

## Milestone 2：设置面板产品化

时间建议：1-2 天

任务：
- 显示固定控制策略状态：使用汽水唯一语义 AX 直控；不可用时安全失败，不提供聚焦兜底开关。
- 增加“诊断模式”设置：显示同步来源、更新时间、进度来源。
- 增加“开机启动/显示灵动岛/重置布局”入口。

验收：
- 设置项修改后立即生效。
- 主岛不出现诊断文案。
- 设置窗口关闭后 CPU 回落。

## Milestone 3：音乐体验稳定性

时间建议：1-2 天

任务：
- 切歌时歌名、歌手、封面做原子更新，避免错位。
- 封面缓存策略升级，避免旧封面残留。
- 进度条继续校准 UI 层，必要时增加临时调试 overlay。
- 验证汽水语义 AX 控件识别的启动开销、失败反馈和系统版本兼容性。

验收：
- 连续切歌 10 次无长期错位。
- 进度条点击展开不回到 0 或几秒。
- 抖音/浏览器视频冲突时不误控视频。

## Milestone 4：计时器 MVP

时间建议：1-2 天

任务：
- 将现有计时器从示例能力做成真实可用功能。
- 支持开始、暂停、重置、加 1 分钟。
- 倒计时结束后通过岛内提醒展示。
- 保持与音乐状态互不干扰。

验收：
- 计时器运行时音乐同步不受影响。
- 计时结束提醒可见、可关闭。
- 展开/收起动画无明显跳动。

## 暂不进入 V0.2 的事项

- 通知中心完整聚合。
- 会议摄像头/麦克风状态。
- App Store 发布与公证。
- 真正无感的汽水内部 IPC 控制；该项继续作为架构研究线。

## 推荐执行顺序

1. 跑 MVP 验收。
2. 修 P0 失败项。
3. 做设置面板产品化。
4. 做音乐体验稳定性。
5. 再进入计时器 MVP。

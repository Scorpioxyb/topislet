# V0.2 开发计划

## 版本目标

V0.2 的目标是把当前可用原型推进为“日常可试用的多音乐应用底座”：稳定汽水音乐体验，建立适配协议，并接入第二款音乐软件。计时器和通知扩展继续延期。

## 版本原则

- 先稳定，再扩展。
- 不伪造状态，不用错误来源覆盖真实来源。
- 控制命令不能误控视频播放器。
- 主界面保持苹果风格，不显示调试文案。
- 诊断信息放在设置或 CLI 中。

## Milestone 1：MVP 验收封版

时间建议：0.5-1 天

任务：
- 跑完 `Docs/MVP_ACCEPTANCE.md` 的 P0 验收。
- 记录失败项到 `Docs/ISSUE_BOARD.md`。
- 对进度、封面、切歌、视频冲突做 1 轮手动录像验证。

交付物：
- MVP v0.1 验收结论。
- 可复现问题清单。
- 当前版本是否可作为日常试用版的判断。

## Milestone 2：设置面板产品化

时间建议：1-2 天

任务：
- 显示固定控制策略状态：使用汽水唯一语义 AX 直控；不可用时安全失败，不提供聚焦兜底开关。
- 增加“诊断模式”设置：显示同步来源、更新时间、进度来源。
- 增加“开机启动/显示灵动岛/重置布局”入口。

验收：
- 设置项修改后立即生效。
- 主岛不出现诊断文案。
- 设置窗口关闭后 CPU 回落。

## Milestone 3：音乐体验稳定性

时间建议：1-2 天

任务：
- 切歌时歌名、歌手、封面做原子更新，避免错位。
- 封面缓存策略升级，避免旧封面残留。
- 进度条继续校准 UI 层，必要时增加临时调试 overlay。
- 验证汽水语义 AX 控件识别的启动开销、失败反馈和系统版本兼容性。

验收：
- 连续切歌 10 次无长期错位。
- 进度条点击展开不回到 0 或几秒。
- 抖音/浏览器视频冲突时不误控视频。

## Milestone 4：音乐适配平台化

时间建议：2-3 天

任务：
- 建立音乐应用描述、原子快照、时间轴、来源证明和控制能力协议。
- 所有控制能力必须绑定明确 Bundle ID 和应用实例，不提供系统当前媒体兜底。
- 设置面板显示已适配和计划接入的音乐应用。
- 以 Apple Music 作为第二个适配器验证协议边界。

验收：
- 汽水现有 35 项自动化测试继续通过。
- Apple Music 接入不需要修改汽水内部状态机。
- 两个适配器不会互相覆盖快照或把控制发送给错误应用。

## 暂不进入 V0.2 的事项

- 通知中心完整聚合。
- 会议摄像头/麦克风状态。
- 计时器正式化。
- App Store 发布与公证。
- 真正无感的汽水内部 IPC 控制；该项继续作为架构研究线。

## 推荐执行顺序

1. 跑 MVP 验收。
2. 修 P0 失败项。
3. 做设置面板产品化。
4. 做音乐适配协议和设置支持列表。
5. 接入 Apple Music 并完成双应用回归。

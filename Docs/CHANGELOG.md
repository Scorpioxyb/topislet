## Unreleased

- 新增隐私友好的日常使用结构化日志：记录来源切换原因、播放器进程生命周期、匿名曲目标识、字段完整性、UI 实际发布时间、控制与 seek 结果和耗时；不记录完整歌名、歌手、歌词或封面。新增 `DailyUsageAnalyzer`，可将最近 24 小时日志汇总为控制成功率、来源抖动以及切歌文本、封面和 seek 的 P50/P95 延迟。
- 恢复汽水音乐进度条的点击 / 拖动跳转。发送前同时校验顶屿当前来源、汽水实时状态、唯一运行 PID、歌曲时长和系统当前媒体焦点；任一条件不满足时保持只读，避免把 seek 发给抖音、QuickTime、浏览器或其他播放器。

- 进度条点击与拖动统一使用零距离手势识别：点击直接走短合并窗口，只有实际位移达到阈值才进入拖拽态，减少点击等待和误触发的视觉卡顿。

### v0.1.2-alpha.1 稳定化

- 汽水专属状态流现在直接携带压缩封面，完整新曲包到达后无需再启动独立 `get-client` 进程补取封面；新歌名配旧歌手、旧专辑、旧时长或旧封面的过渡包仍由原子门控拒绝。三组同事件 A/B 中完整发布平均由约 `567ms` 降至 `336ms`，最终 Release 安装版三次为 `344/343/345ms`。
- 封面 UI 缓存改为 ImageIO 最长边 256px 下采样、4 项 LRU 和 1MB 解码成本硬上限；封面主色移除全局 Core Image / Metal 路径，改为 32px CPU 采样。20 次切歌资源回归中 RSS 最终 `-1.26%`、physical footprint 最终 `+5.82%`、告警 0。
- 显示器热变化现在会立即作废旧窗口动画、重算目标屏幕与几何，并在约 `150ms` 和 `650ms` 做有界稳定化复核，避免热插拔过渡态或迟到动画 completion 把岛留在旧 frame。显示器绑定和校准优先使用物理显示器 UUID，重连后系统屏幕编号变化不会被误认为新设备；排列原点变化继续复用原校准，缩放档位仍独立保存。首次升级会无损迁移旧屏幕编号下的校准值，已有 UUID 校准不会被旧数据覆盖。
- 顶屿现跟随 macOS“减少动态效果”设置：开启后，紧凑、展开和收回的窗口几何改为即时稳定切换，内容只保留约 `40-50ms` 的短透明度反馈；关闭后继续使用原有 `240ms / 180ms` 动画。系统设置变化会被实时监听，无需重启 App，常规设置页同步显示当前状态；窗口动画门禁会按系统状态分别校验“无中间帧”或“连续插值”。
- 设置“常规”新增集中式权限状态与恢复入口，可打开辅助功能、Apple Music 自动化、日历和提醒事项的系统设置并重新检查状态；新增带确认的“恢复当前屏幕默认布局”，不会清除音乐适配、登录项或其他屏幕配置。
- 设置“常规”新增“登录时自动启动顶屿”：使用 macOS `SMAppService.mainApp` 注册主 App，不写入私有启动脚本；开关直接反映系统登录项状态，并处理等待批准、安装不可用和注册失败。
- 修复辅助功能授权失效后音乐控制按钮变成不可点击：汽水和网易云按钮在控制权限失效时保留可点击的恢复入口，触发 macOS 辅助功能检查并打开对应设置页；主循环自动刷新授权状态，授权恢复后重新启用来源专属控制。新增权限恢复策略测试，当前共 `209` 项自动化测试通过。
- 修复 Apple Music 1.6.5 电台元数据异常：PID 地址的 ScriptingBridge 会长期返回 `ATEEZ` 等电台占位，而同一 Music 进程的 Bundle 地址返回真实当前歌曲。快照读取现只在目标已运行时使用 Bundle 地址，并在读取前后校验原 PID；播放、暂停、切歌和进度控制继续严格绑定点击时的 PID 与曲目身份。
- Apple Music 普通元数据读取不再同步等待封面 Apple Event；原生封面获得 350ms 优先窗口，超时后与 Apple 公共目录精确匹配并发竞速，原生明确无封面时立即取消剩余等待并启动目录查询。成功结果仍校验 Music PID、曲目身份和请求代次，迟到封面不能覆盖新歌。
- Apple Music 电台只返回标题、缺少歌手和专辑的占位快照时，按 `250ms / 600ms / 1.2s / 2.4s` 有界重试并保留上一完整歌曲；重试耗尽后允许降级接受，避免合法无艺人本地文件永久卡住。
- `--apple-music-status` 新增元数据、原生封面、目录搜索和下载的 transition timeline；只有真正拿到封面才报告 `artworkLatencyMilliseconds`，无可匹配封面显示 `unavailable`，不再把固定诊断等待误报为 5 秒封面延迟。
- ATEEZ 电台 `BOUNCY (K-HOT CHILLI PEPPERS)` 实测元数据 `258ms`、原生无封面确认 `172ms`、目录精确匹配与下载 `240ms`，总封面 `758ms`；普通歌曲封面约 `471-537ms`。安装版暂停即时切换并冻结进度，下一首 `Dreams Come True → Janice STFU` 在约 `0.85s` 内完成文本、歌手、时长和封面原子收敛。
- 修复多显示器环境下鼠标或焦点改变 `NSScreen.main` 后，展开、收回和动画纠偏把岛迁移到另一显示器的问题。岛现在稳定绑定首次选定的摄像头屏幕；显示器仍存在时主屏变化不影响位置，仅在绑定屏幕消失时优先回退到带摄像头模组的内屏。
- 修复顶屿先启动、网易云后启动时观察流可能在 MediaRemote 客户端注册前完成绑定的问题：新 PID 出现后立即重建，首次取得该 PID 的有效快照后再次重建；网易云运行期间保留 PID 定向轻量校验，未选中且暂停或未知时以 `0.5s` 发现间隔兜底，瞬时空读在 `90ms` 后原地重试，存活但沉默的流不再长期冻结播放状态。
- Chrome 抖音、Safari 本地有声媒体页和 QuickTime 并发播放回归中，岛内播放 / 暂停、上一首和下一首均保持绑定汽水专属 PID，浏览器与视频播放未被暂停或切换。
- 当前 209 项自动化测试通过，Release 构建、ad-hoc 签名、辅助功能授权继承和安装版启动验证通过。双屏实机动画门禁保持内屏 `855.5pt` 锚点；内屏运行中从 `1710×1107pt` 切换至 `1440×932pt` 再恢复，全程 PID 不变，岛自动更新到 `720pt` 后回到 `855.5pt` 锚点，两种分辨率的单窗口动画门禁均通过。

### v0.2.0-dev 网易云音乐 Alpha 支持

- 新增按 `com.netease.163music` Bundle ID 与当前 PID 定向的网易云音乐专属状态桥，可读取歌名、歌手、专辑、封面、播放状态、进度和时长；系统当前媒体源与其他视频应用不能进入该快照。
- 新增网易云进程内原生“控制”菜单适配，播放 / 暂停、上一首和下一首均绑定点击时的 PID 与歌曲身份，不发送全局媒体键、不激活应用、不移动鼠标。
- 音乐来源路由扩展为汽水、网易云音乐和 Apple Music；前台已适配音乐应用立即切换，离开后按真实播放状态选择，未适配视频应用不参与控制目标。
- 网易云切歌增加事务门控：拒绝“旧歌名 / 旧封面 + 新时长”的混合快照，完整元数据与封面一起发布；不同封面可作为强确认，同封面歌曲继续双快照确认。
- 本机网易云音乐 `3.1.8 (3368)` 实测专属读取约 `42ms`，下一首和上一首完整原子切换分别为 `0.761s` 与 `0.758s`。
- 设置音乐页新增网易云运行、辅助功能、连接与可用控制状态；新增 `--netease-music-status`、`--netease-music-semantic-control` 和 `--netease-music-adapter-control` 诊断命令。
- 网易云 Alpha 当前进度保持只读，不声明或调用系统全局进度跳转。
- 网易云启动或重新激活时，专属 MediaRemote client 尚未就绪会执行 `350ms / 700ms / 1.2s` 有界短重试；应用退出后仍立即清除旧歌曲。
- 修复顶屿先启动、网易云后启动或重启时专属状态流仍绑定旧会话的问题：首次取得新 PID 有效快照后重建 `stream-client`，运行但尚无曲目时继续做 PID 定向发现，漏事件不再依赖重新激活应用恢复。
- 网易云新 PID 首次播放增加 5 秒有界收敛窗口和 `200ms / 500ms / 1s` 重绑确认，拒绝迟到 `paused` 长期占住来源；稳态当前来源每秒最多一次轻量校验，曲目变化才读取封面并原子提交。
- 网易云后台同专辑、同封面切歌与 Chrome 视频并存复验通过；Chrome 保持播放，网易云暂停 / 恢复只命中其当前 PID。
- 网易云播放中切歌时会先发送 `paused + 30s 临时时长`，随后才补齐 `playing + 真实时长`；切歌事务现保留上一首完整状态并在 2.2 秒有界窗口内等待播放确认，避免按钮闪为暂停或进度短暂套用占位时长。
- 网易云前台激活触发的权威元数据刷新也统一进入切歌事务，不再绕过暂停占位门控；真实“私人漫游”已通过前台切歌、后台岛内切歌、自然续播、封面、进度及暂停恢复验收。
- QuickTime 或抖音抢占系统媒体焦点时，网易云同曲稀疏事件不再把播放态改成暂停或清空时间线与封面；岛保持最近权威状态并触发完整 PID 定向回读。实测岛内暂停网易云时，QuickTime 和抖音继续独立播放。
- 窗口布局改为运行时读取 `NSScreen.safeAreaInsets` 与两侧 `auxiliaryTop*Area`，以真实摄像头区域中心和尺寸定位；无刘海外接屏使用顶部居中胶囊，不再把固定的 15 英寸参数套用到所有屏幕。新增 `--display-geometry` 只读诊断和 Air 13/15、Pro 14/16 布局测试矩阵。
- 网易云异步确认回归不再依赖固定 `250ms` 测试休眠，改为最多 1.5 秒的有界完成条件等待；产品读取和切歌超时策略未改变，消除 GitHub Runner 负载差异造成的偶发失败。
- Apple Music 连续切换同一艺人、同一专辑的歌曲时复用最近已验证封面，并写入新曲目身份缓存；避免相同封面重复请求 Apple 目录和约半秒的占位图阶段。不同艺人、不同专辑或缺失专辑身份时严格拒绝复用。
- Apple Music 封面回退改为按当前歌曲身份管理：原生封面缺失后才进入公共目录，目录失败只为仍在播放的同一歌曲执行一次原生回读；空状态、旧歌曲迟到失败和快速连续切歌不能污染新歌曲，也不会形成原生与目录无限循环。
- 当前 141 项自动化回归测试通过，开发安装包重新签名与严格验证通过。

### v0.1.1-alpha.4 Apple Music Alpha 支持

- 顶部胶囊和展开主体由双窗口重构为单一 `NSPanel`，展开/收回始终保持顶边和屏幕中心不变，悬停与外部点击使用明确的 Header、Body 和窄桥区域。
- 恢复单窗口从紧凑尺寸到展开尺寸的连续插值轨迹，保留顶部与水平中心锚定；窗口整体长出并带动内容形变，不再瞬时切换透明画布。
- 悬停展开响应缩短到约 50ms，保持单窗口连续形变；快速反向切换仍由动画代次保证最终位置和尺寸正确。
- 动画完成回调增加代次与目标模式双重门禁，快速反向切换时旧 completion 不再覆盖最新窗口 frame。
- CI 开始运行 `swift test`；Release 候选增加精确 tag、干净工作区与测试门禁，DMG 校验增加版本号和构建号。
- 修复 Documents 文件提供器为开发包重新附加扩展属性时阻断 `/Applications/顶屿.app` 安装验证的问题。
- 修复汽水窗口最小化后 AX 树退化导致三种控制全部安全拒绝：只对唯一标准窗口后台临时恢复，控制完成后重新最小化，不激活汽水、不移动鼠标。
- 独立抖音 App 前台播放回归通过：视频持续播放，汽水暂停/恢复、下一首和上一首均只命中汽水。
- 新增按 Apple Music 进程 PID 定向的 Apple Event 适配器，可读取歌曲、播放状态和时间轴，并支持播放 / 暂停、上一首、下一首和绝对进度跳转；不会自动启动 Music，也不会使用系统当前媒体控制。
- 新增汽水与 Apple Music 自动来源选择：两者同时播放时汽水优先；汽水暂停而 Apple Music 播放时自动切换；退出应用或进程实例变化时立即废弃旧路由。
- 新增前台应用优先路由：切到汽水窗口时岛立即显示汽水，切到 Apple Music 时立即显示 Apple Music；离开两个音乐应用后恢复播放状态兜底。控制目标与岛当前显示来源保持一致。
- 按钮与进度操作绑定点击瞬间岛实际显示的来源：汽水固定到具体 PID，Apple Music 固定到具体 PID 与曲目身份；目标失效时安全拒绝，不再在点击后重新选择或改投其他应用。
- 前台应用身份先立即切换，歌曲与封面再异步补齐；前台 Apple Music 在权限或快照未就绪时仍保持 Apple Music 空闲状态。异步控制结果只在岛仍显示原应用时更新界面。
- Apple Music 新增定向专辑封面读取：按曲目身份缓存原始图片，只在缓存缺失时额外读取；读取前后歌曲 ID 不一致时丢弃结果，封面失败不会影响歌名、进度或控制。
- Apple Music 电台曲目没有脚本封面时，后台通过 Apple 公共 iTunes Search 按歌名、歌手和专辑唯一精确匹配，并从 Apple CDN 下载 600px 封面；模糊、歧义或非 Apple HTTPS 地址一律拒绝。
- 已确认处于“电台无原生封面”会话后，下一首的 `playerInfo` 通知会立即并行预取目录封面；权威 Apple Event 快照仍负责最终曲目身份门禁。普通原生封面则与切歌元数据在同一次快照返回，稳态轮询不读取封面。
- Apple Music 原生封面与切歌元数据改为单次定向快照，本机实测约 265-300ms 同时返回；电台目录封面仍异步补齐，只替换图片，不重锚进度、刷新控制验证时间或覆盖乐观播放状态。
- 封面请求标记会在请求发起时消费，旧请求完成不再清除执行期间到达的新切歌通知；岛内封面更新移除额外 160ms 淡入等待，数据到达后直接替换。
- `playerInfo` 切歌通知会立即启动绑定 PID 与完整曲目 ID 的原生封面预取，60ms 只用于合并 UI 刷新通知；避免轻量时间轴请求先发布长时间占位图，岛内上一首 / 下一首也不再同时追加第二个重型封面快照。
- 原生、目录与普通后台封面读取增加双向 in-flight 去重；目录失败遵守 30 秒临时失败和 5 分钟无匹配退避，区域端点超时后不再立即追加第二次全局超时。
- Apple Music 播放 / 暂停加入点击即刻的本地乐观反馈，实际 Apple Event 仍绑定点击瞬间的 PID、应用实例和曲目身份并串行执行；旧操作失败不会回滚新操作。
- Apple Music 轮询改为通知优先、单请求加完成时间节流：重复 `playerInfo` 通知先合并，播放中每 5 秒、暂停 10 秒、后台 15 秒才做一次兜底读取，控制确认仍使用短时定向回读；连续失败自动退避，避免高频 Apple Event 干扰 Music 电台与商店状态。
- Apple Music 电台切歌期间若同一进程的定向读取返回瞬时 `.degraded` 或 `409` 混合快照，保留最近可信歌曲并按 `250ms`、`600ms`、`1.2s`、`2.4s` 有界短重试；退出、PID 变化、权限错误和重试耗尽仍立即正常降级。ATEEZ 电台实测在 `683ms` 发布新歌、`1156ms` 补齐目录封面，期间不再回退到暂停的汽水。

- 语义化 AX 成为唯一产品控制通道：只绑定汽水 PID，并根据角色、结构和相邻控件特征选择唯一目标；唯一控件不可证明或辅助功能权限不可用时安全失败。
- 移除“实用模式 / 严格模式”、短暂激活汽水和全局媒体键运行路径。
- MediaRemote Adapter framework 更新为 `arm64` + `x86_64` Universal 二进制。
- 切歌元数据改为暂存后原子发布：新歌名出现但歌手或封面仍属于旧曲时，继续保留上一完整画面，待元数据一致后统一提交。
- 语义 AX 控制、播放回读和控件扫描均移出主线程；控制点击立即显示按压反馈，上一首和下一首使用独立操作代次，但不显示等待环。
- 模式点击冷却从 720ms 缩短到 80ms，控制后的模式抑制从 280ms 缩短到 60ms，改善连续点击响应。
- 收窄折叠、紧凑和展开尺寸；展开上下窗口以 3pt 重叠形成连续黑色轮廓，统一黑度、描边、圆角，并压缩计时器和提醒布局。
- 状态绿点改为白色微型波形，避免与 macOS 摄像头隐私指示灯混淆。
- 优化进度条单击跳转：单击与拖动使用独立手势，点击不再触发圆点缩放脉冲；单击采用更短的 seek 合并窗口，并保持即时本地预览和最终操作优先。
- 优化进度条拖动手感：拖动预览与时间标签同步，seek 和常规播放位置回读移出主线程，连续 seek 串行执行并带超时；命令确认前保持目标位置，避免松手卡顿和旧进度回弹。
- 修复播放/暂停后的时间回退：控制命令使用带操作代次和时间锚点的乐观播放状态，MediaRemote 仅用命令后的新样本确认，缓存样本只负责显示；暂停进度单调稳定，连续快速点击基于上一次目标状态反转。
- 设置面板显示固定的“汽水语义控件直控”策略，并可隐藏 / 显示音乐诊断信息。
- 音乐诊断模式新增 UI progress、elapsed、duration、canSeek、pending、封面字节数，并支持一键复制诊断信息。
- 优化切歌元数据稳定性：封面补齐回包必须匹配当前曲目，封面视图按曲目与封面身份刷新，减少旧封面残留。
- 修复音乐进度识别：AX 兜底不再把汽水窗口中的列表/旧歌时间误当成当前播放进度；主界面进度只使用 MediaRemote Adapter 的可信 elapsed/duration。
- 媒体焦点被其他播放器抢占时继续使用汽水客户端专属流，避免用其他 App 的 Now Playing 覆盖汽水状态。
- 修复点击/展开灵动岛时进度条视觉上从 0 重新开始的问题：非拖动状态下进度条禁用隐式宽度动画，直接显示当前可信进度。
- 修复点击岛时进度被 fallback 状态刷回 0 的问题：切换折叠/展开前先刷新当前可信播放状态，并阻止无 `elapsedTime/duration` 的 AX/placeholder 状态覆盖已有 MediaRemote 进度。
- 修复点击岛后进度显示成开头几秒的问题：折叠/展开前改为同步刷新一次 MediaRemote Adapter 播放位置，并在播放中每约 2 秒校准一次真实 elapsed/duration。
- 优化汽水 AX 监听：不再每 2 秒强制重扫可访问性树，减少观察节点和通知类型，降低同步抖动与后台开销。
- 进度跳转在不能确认汽水为可跳转目标时保持阻断，避免 seek 误控视频播放器；汽水专属定向 seek 仍是后续底层任务。
- 修复抖音/Chrome 视频页并行时主 App 高 CPU、灵动岛点击无响应的问题：常规 UI tick 不再同步拉取 MediaRemote/AX，音乐状态发布改为事件驱动加低频进度刷新。
- 启动时不再自动打开设置窗口；设置/校准窗口关闭后释放 SwiftUI 内容，避免隐藏窗口继续重排拖慢灵动岛。
- 修复布局校准自触发循环：屏幕信息未变化时不再重复发布 `currentDisplayName`、`notchWidth` 和 `topBandHeight`，主 App 稳态 CPU 恢复到低占用。
- 新增产品需求文档、路线图、QA 检查清单。
- Git 忽略第三方 App 解包产生的本地 JavaScript 调查文件，避免把专有产物纳入产品仓库。

# 变更记录

## Unreleased

- 修复音乐进度识别：AX 兜底不再把汽水窗口中的列表/旧歌时间误当成当前播放进度；主界面进度只使用 MediaRemote Adapter 的可信 elapsed/duration。
- 媒体焦点被其他播放器抢占时，最近一次可信汽水进度会按播放态本地推进，不再冻结在旧位置。
- 修复点击/展开灵动岛时进度条视觉上从 0 重新开始的问题：非拖动状态下进度条禁用隐式宽度动画，直接显示当前可信进度。
- 修复点击岛时进度被 fallback 状态刷回 0 的问题：切换折叠/展开前先刷新当前可信播放状态，并阻止无 `elapsedTime/duration` 的 AX/placeholder 状态覆盖已有 MediaRemote 进度。
- 修复点击岛后进度显示成开头几秒的问题：折叠/展开前改为同步刷新一次 MediaRemote Adapter 播放位置，并在播放中每约 2 秒校准一次真实 elapsed/duration。
- 优化汽水 AX 监听：不再每 2 秒强制重扫可访问性树，减少观察节点和通知类型，降低同步抖动与后台开销。
- 新增 QuickPlayer/QuickTime 媒体焦点冲突保护：系统 Now Playing 被视频播放器抢占时，灵动岛短时保留最近一次可信汽水音乐状态，不再被清空，且冲突期间冻结进度避免假进度。
- 控制命令增加安全预检：未确认 macOS 媒体焦点在汽水音乐时，不发送播放/暂停、切歌或进度跳转，避免误控视频播放器。
- 发现 `MRNowPlayingClient` 定向控制只在 `swift -e` 解释器探针中可用，普通 App 二进制拿不到 client 列表；当前运行时保留为诊断入口，不作为已交付控制路径。
- 新增汽水专属聚焦兜底：当其他媒体抢占系统 Now Playing 时，灵动岛会短暂激活汽水音乐发送播放/暂停、上一首、下一首，再恢复原 App，实测可切换汽水真实播放态。
- 修复抖音/Chrome 视频页并行时主 App 高 CPU、灵动岛点击无响应的问题：常规 UI tick 不再同步拉取 MediaRemote/AX，音乐状态发布改为事件驱动加低频进度刷新。
- 启动时不再自动打开设置窗口；设置/校准窗口关闭后释放 SwiftUI 内容，避免隐藏窗口继续重排拖慢灵动岛。
- 进度跳转在系统媒体焦点不是汽水时会被阻断，避免把 seek 发送给视频播放器；定向 seek 作为下一轮底层能力继续调查。
- 修复布局校准自触发循环：屏幕信息未变化时不再重复发布 `currentDisplayName`、`notchWidth` 和 `topBandHeight`，主 App 稳态 CPU 恢复到低占用。
- 新增产品需求文档、路线图、QA 检查清单。
- Git 忽略第三方 App 解包产生的本地 JavaScript 调查文件，避免把专有产物纳入产品仓库。

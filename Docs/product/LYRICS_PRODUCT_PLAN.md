# 顶屿歌词产品方案

状态：Goal 开发中（2026-10-02）

## 1. 目标

歌词不是展开面板里的附属信息，而是音乐活动在顶部区域的第一层信息。用户在听歌时不展开顶屿，也应能看到当前句；展开后再获得下一句、来源和完整控制。

本阶段的成功标准：

- 有可信歌词时，收起态和紧凑态均能看到当前句。
- 紧凑态根据歌词可读性进入更宽的音乐布局，不把歌词压进 96pt 小翼。
- 没有歌词时回退到歌曲名/歌手，不显示伪造或占位歌词。
- 歌词异步到达、切歌、歌词消失时，窗口只发生一次稳定重排，不持续抖动。
- 全屏视频、其他桌面空间、多显示器和无刘海屏仍遵循现有隐藏与几何策略。

## 3. 产品模型

### 三个呈现层

1. **收起态**：保持原有左右图标/状态点和点击区域；音乐有可信当前句时使用中间空区显示单行歌词，超出可用宽度时缓速滚动。
2. **紧凑态**：音乐活动进入歌词宽档。左翼保留小封面，只显示一条可读的当前主歌词；右翼保留进度与状态。译文和下一句留给展开态，避免在 33pt 顶栏里形成被裁切的双行黑边。长句滚动展示，不以缩小字体代替阅读。
3. **展开态**：保留封面、进度和控制；歌词区域显示当前句、可验证的译文/下一句，并标记是否来自桌面歌词快照。

### 尺寸策略

- 普通紧凑态：两侧翼 96pt，兼容计时器、通知和无歌词音乐。
- 歌词紧凑态：左翼 320pt、右翼 96pt，岛宽度由 `notchWidth + 416pt` 得出；把空间给歌词，不浪费在右侧空白。
- 宽档只在当前句真实可显示时启用；歌词为空或歌曲切换到无歌词时回退普通档。
- 顶部高度仍由 `safeAreaTop`、摄像头区域和显示缩放计算，不因歌词增加纵向高度。
- 紧凑态当前主句使用 18pt 字号、24pt 行框，在 33pt 顶部栏内上下各保留 4pt 安全边距；文本溢出时按溢出宽度以 80-200pt/s 滚动，首尾各停留 0.25 秒。无滚动溢出的短句保持静止。译文/下一句只在展开歌词栏显示。

## 4. 数据与软件适配

歌词来源优先级保持：

1. 已验证的 MediaRemote 汽水歌曲身份与歌词。
2. 同 PID、同歌曲名/歌手校验的汽水 AX 可见歌词。
3. 桌面歌词快照作为标记了来源的只读补充。

行同步规则：优先使用汽水可访问性树明确标记的 active 当前行。缺少当前行标记时，不把页面上任意前两行猜成当前/下一句；宁可暂时隐藏歌词，也不显示错句。所有 AX fallback 都必须绑定当前 PID、曲名和歌手。

主播放器与桌面歌词的唯一 `active` 行都必须命中该曲目双读确认过的歌词语料；不命中时隐藏，不沿用上一句。桌面歌词段落节点按 3 秒节流重发现，当前活动行仍以 250ms 周期采样。

每次发布前都必须满足：

- 歌曲身份不匹配时丢弃歌词快照。
- 歌曲身份不匹配或缺少明确当前行时，丢弃歌词快照而不沿用旧歌词。
- 占位文本由 `MusicLyricPresentation.clean` 过滤。
- 歌词异步发布不改变播放控制权限和按钮可用性，也不得再次触发完整 AX 树扫描。
- 播放器退出、前台切换或全屏抑制不自动重新打开播放器。

## 5. 系统适配矩阵

| 场景 | 预期 |
| --- | --- |
| 内建刘海屏 | 宽档居中于真实摄像头区域，文本不越过安全边界。 |
| 无刘海屏/外接屏 | 使用合成 notch 宽度和菜单栏顶部高度，仍可读且不刺穿菜单栏。 |
| Retina 缩放 | 宽度和顶部高度按 backing scale 对齐像素。 |
| 多桌面切换 | 继续遵循 collection behavior 和全屏抑制，不在不属于当前空间的视频上出现。 |
| 原生全屏视频 | 岛隐藏，不拦截视频交互；退出后恢复此前音乐呈现层。 |
| Reduce Motion | 关闭尺寸过渡动画但保持最终宽度和点击区域可用。 |

## 6. 分阶段实施

### P0：歌词可见性与宽档（本轮）

- 收起态中间空区显示当前句。
- 紧凑态歌词左翼 320pt，右侧保持 96pt；当前主句使用单行 24pt 内容框，译文不再挤入顶部栏。
- 歌词出现/消失只触发一次 panel resize。
- 增加数据层和布局层测试。

### P1：可读性与来源状态（本轮）

- [x] 统一中英双语分行策略，当前句与下一句分别处理；译文索引会回溯到对应主句。
- [x] 为歌词来源增加轻量可访问性标签，区分当前同步歌词和汽水桌面歌词快照。
- [x] 增加双语配对、同语言连续歌词和宽度档位单元测试。
- [ ] 在真实歌词、长句、无歌词、切歌和桌面歌词快照场景做实机截图验收。

### P2：可选扩展

- 用户可在设置中选择普通紧凑档或歌词宽档上限。
- 评估跟随系统文字大小和更宽的超长歌词档位。
- 仅在歌词链路稳定后评估本地 AI 歌词摘要/翻译，不把网络模型放进默认播放链路。

## 7. 验收矩阵

- `swift test --quiet` 全部通过。
- `git diff --check` 通过，控制安全脚本通过。
- 内建刘海屏、无刘海/外接屏各验证收起/紧凑/展开三态。
- 有歌词歌曲显示当前句；无歌词歌曲不出现占位文本。
- 歌词从无到有、切歌、从有到无时 panel 只重排一次且无黑边。
- 原生全屏视频时隐藏，退出后恢复；不再使用百度网盘作为验证对象。
- Release 打包、签名、安装后再做一次真实汽水流媒体检查。

## 8. 明确不做

- 不把歌词塞进展开面板作为唯一入口。
- 不为显示歌词引入 OCR、MITM、ASAR 修改、token 提取或全局媒体键。
- 不因为歌词功能加入电池、音量、亮度等系统已有状态。
- 不在本轮同时扩展 AI、天气、文件暂存等新活动源。

# 顶屿 0.2 产品重规划

**状态：部分被取代（2026-11-13）。原为提案基线（2026-09-23）**  
**适用版本：`main`，当前本地版本 `0.1.3 build 40`**

> **2026-11-13 起**：第 1 节定位、第 6 节 AI Command Bar、第 7 节功能路线已被[2026-11 全局规划](GLOBAL_PLAN_2026-11.md)取代（定位改为“音乐优先的刘海岛”，AI Command Bar 移到 1.0 之后再议）。第 2 节恢复契约、第 4 节仲裁规则、第 5 节音乐边界、第 8 节权限分级继续有效。

## 1. 结论先行

> 本节定位已被[2026-11 全局规划](GLOBAL_PLAN_2026-11.md) 2.1 取代。

顶屿不再沿着“支持更多音乐 App”的单线扩展。新的定位是：

> 顶屿是位于 MacBook 刘海区域的低打扰活动操作层。音乐是一个高频活动适配器，但不是顶屿成立的前提。

这次重规划要解决的不是再加一个播放器按钮，而是两个产品级断点：

1. 汽水音乐关闭、窗口隐藏或辅助功能树不可用时，顶屿仍然必须有独立价值。
2. 任何外部 App 的恢复都必须是用户明确发起的动作，不能由后台状态检查重新打开或激活。

因此 0.2 先做“独立可用性 + 统一活动引擎”，再做 AI 命令入口，最后才考虑开发者活动和更多系统 HUD。

### 功能筛选原则

- 不复制 macOS 已经放在右上角、控制中心或系统 HUD 中且触达成本很低的状态，例如电池、音量和亮度。
- 只有当顶屿能提供更短路径、更好的上下文，或系统原生没有对应工作流时，才新增功能。
- 当前更值得优先验证的是文件 Shelf、剪贴板暂存、快速笔记、打开当前工作 App 和本地命令入口。

### 本轮已落地

- 音乐有歌曲但定向控制全部不可用时，折叠岛点击自动降级到活动中心。
- 活动中心提供“音乐控制暂不可用”状态和用户主动恢复入口。
- 恢复入口明确说明只在用户点击时重启一次汽水并启用其 Electron AX 树；恢复行增加后，活动中心高度同步扩展，避免内容裁切。
- 顶屿面板不再加入其他 App 的全屏空间，并增加覆盖窗口抑制层；视频全屏或播放器伪全屏时隐藏，退出全屏后恢复。
- 新增策略测试覆盖不可用控制的降级路由，并保留后台不打开汽水的既有契约测试。

## 2. 当前状态与证据

### 已经成立的能力

- 当前项目已经有音乐、计时器、日历/提醒活动和活动中心入口。
- 汽水控制使用定向 Accessibility 语义控件，并要求唯一、可验证的控件组；不使用全局媒体键作为默认路径。
- `build 40` 已把“后台自动打开汽水”改为“仅用户点击恢复播放控制时才打开”。
- 汽水窗口关闭时，状态流可以继续存在，但控制能力必须安全降级为不可用。

### 仍然存在的结构性问题

- `IslandFeature`、`IslandModel` 和音乐仲裁仍然以音乐来源为中心，活动之间靠特判切换。
- 音乐源不可用时，顶屿的可操作内容不足，用户自然会认为“必须开着汽水才能用”。
- “汽水进程未运行”“窗口关闭”“控件树暂不可用”“权限缺失”在用户体验层仍容易被理解为同一种故障。
- 现有代码和文档中仍有“打开汽水音乐后自动恢复”一类旧文案，需要统一为“用户主动恢复”。

### 本轮对用户反馈的解释

用户观察到的“关闭后又弹出来”不应被当作正常恢复逻辑。正确的产品契约是：

| 状态 | 顶屿行为 | 是否打开/激活汽水 |
| --- | --- | --- |
| 汽水播放、控件可验证 | 显示并允许定向控制 | 否 |
| 汽水进程存在、主窗口关闭 | 保留只读活动或显示降级状态 | 否 |
| 汽水控件树暂不可用 | 控件禁用并提供用户触发的恢复入口 | 否 |
| 用户点击“重启并连接播放控制” | 带 `--force-renderer-accessibility` 重启汽水并重新验证控件 | 是，仅此时 |
| 后台轮询、状态刷新、切换前台 App | 更新状态或降级，不产生外部窗口副作用 | 否 |

这个契约必须由单元测试、日志断言和实机验收共同保护。

## 3. 竞品调研与取舍

本轮查看了公开 GitHub 项目和 Apple 官方能力文档。以下是对顶屿真正有价值的模式提炼，而不是照搬功能列表。

| 项目/来源 | 已观察到的方向 | 对顶屿的启示 | 不直接照搬的部分 |
| --- | --- | --- | --- |
| [BoringNotch](https://github.com/TheBoredTeam/boring.notch) | 音乐、日历、文件 Shelf、AirDrop、系统 HUD | 顶部区域应承载多个短时活动 | 不同时引入大量扩展和权限 |
| [DynamicNotch](https://github.com/jackson-storm/DynamicNotch) | Now Playing、下载、AirDrop、计时、Focus、录屏、蓝牙/Wi-Fi/VPN HUD、手势 | “Live Activity + 临时 HUD + 手势”比播放器专属面板更稳定 | 不把屏幕录制、网络和隐私权限默认打开 |
| [gh-notch](https://github.com/aymandakirgh/ghnotch) | 本地优先 AI Command Bar，可选 Ollama/OpenAI-compatible endpoint | AI 应是顶部命令入口，且要区分本地/远程结果 | 不默认配置云模型，不把聊天窗口塞进岛 |
| [MacDynamicIsland](https://github.com/chenjieliefu/MacDynamicIsland) | 剪贴板、截图、快速笔记、运行中 App、相机镜像 | 系统小工具能让顶屿脱离音乐独立成立 | 相机、屏幕录制等功能按需延后 |
| [NotchMore](https://github.com/Codseus/NotchMore) | 每项功能可选、首次选择功能、按需申请权限 | 权限必须随功能启用，而不是随 App 启动 | 不一次性复刻所有工具 |
| [Coder Island](https://github.com/luokebi/coder-island) | Claude/Codex 状态、权限请求、问题回答、终端跳转、用量、智能抑制 | 可形成独立的开发者模式，且要避免终端已在前台时打扰 | 不默认给普通用户展示 Agent 权限流 |
| [Apple App Intents](https://developer.apple.com/documentation/appintents) | 动作可进入 Siri、Spotlight、Shortcuts、Widgets、Controls 等系统入口 | AI 之前先把顶屿动作做成系统可调用能力 | 不把 Apple Intelligence 当作唯一入口 |
| [EventKit](https://developer.apple.com/documentation/eventkit) | 日历和提醒的读写与变化通知 | 现有日历/提醒源可以升级为独立活动源 | 不默认读取全部事件或全部通知 |

### 调研判断

市场上成熟的同类产品共同点不是“音乐适配更多”，而是：

1. 有一个与外部 App 解耦的活动容器。
2. 活动有优先级、生命周期、自动消失和恢复策略。
3. 系统能力和 AI 都是可选入口，权限按功能懒申请。
4. 用户已经在前台处理事情时，产品会主动抑制打扰。

## 4. 新的产品模型

### 四层结构

```text
顶屿 Shell（常驻、几何、动效、点击区域）
        |
活动引擎（优先级、生命周期、呈现、恢复、抑制）
        |
活动源（计时器 / 日历 / 提醒 / 下载 / 系统 HUD / 音乐 / Agent）
        |
来源适配器（汽水 / Apple Music / 网易云 / EventKit / NSWorkspace / 本地命令）
```

### 活动源必须具备的契约

后续不再给每个功能添加 `switch` 特判。统一活动源至少要描述：

```swift
protocol IslandActivitySource {
    var id: String { get }
    var priority: Int { get }
    var sourceHealth: ActivitySourceHealth { get }
    var requiredPermissions: [IslandPermission] { get }
    var userInitiatedOnly: Bool { get }
    var dismissPolicy: ActivityDismissPolicy { get }
    var restorePolicy: ActivityRestorePolicy { get }
    var collapsedPresentation: ActivityPresentation { get }
    var expandedPresentation: ActivityPresentation { get }
    var actions: [ActivityAction] { get }
}
```

建议的健康状态：`healthy`、`degraded`、`needsPermission`、`notRunning`、`unavailable`。健康状态只影响该活动源，不得让 Shell 崩溃、卡死或自动打开外部 App。

### 活动仲裁规则

- 用户直接操作 > 用户固定展开的活动 > 高优先级短时活动 > 普通背景活动。
- 计时器运行中，普通音乐状态不能夺取主呈现。
- 日历/提醒只在临近或到期时短暂接管，结束后恢复上一个仍有效的活动。
- 外部 App 关闭后，活动源可以保留最后一次可信快照或进入降级状态，但不得擅自恢复外部 App。
- 展开态中用户正在拖动、点击或等待控制回读时，后台活动不得抢占。
- 终端/IDE 已经在前台时，开发者活动默认不自动展开。

## 5. 音乐适配器的边界

音乐继续保留，但从“产品基座”降级为“一个活动源”。

### 汽水关闭后的目标体验

- 岛仍可打开活动中心、计时器、日历、提醒和系统快捷操作。
- 音乐活动显示明确的状态：`只读`、`控件不可用` 或 `未运行`，不显示看似可点击但无效的黑色按钮。
- “恢复播放控制”是显式动作，点击后才允许 `NSWorkspace` 打开或激活汽水。
- 恢复流程必须有超时、失败反馈和取消，不得在后台重试拉起窗口。
- 恢复失败不影响其他活动源；用户可以继续使用顶屿的本地功能。

### 不再扩张的方向

- 暂停无限增加播放器适配。
- 不使用 OCR 作为主要同步链路。
- 不依赖非公开 MediaRemote 能力承诺跨 App 的完整定向控制。
- 不把“播放器窗口存在”当作顶屿交互可用性的前提。

## 6. AI Command Bar 方案

> 本节已被取代：AI Command Bar 移出路线图，1.0 之后再议（[2026-11 全局规划](GLOBAL_PLAN_2026-11.md)决策 2）。

AI 可以加入，但第一版不是聊天机器人，而是“顶部命令入口”。

### 分层执行

1. **本地固定命令（默认）**：计时器、打开 App、截图、快速笔记、剪贴板存入 Shelf、字数统计、文本转换、查看下一日程。
2. **App Intents / Shortcuts**：把顶屿动作暴露给系统自动化和 Siri/Spotlight。
3. **本地模型（可选）**：用户配置 Ollama 等本地端点后，解析复杂自然语言。
4. **远程模型（可选）**：仅使用用户主动配置的 OpenAI-compatible endpoint；显示“本地/远程”标识。

### 第一批可验证命令

- “开始 25 分钟专注。”
- “25 分钟后提醒我休息。”
- “打开汽水音乐。”
- “把当前剪贴板转成三条要点。”
- “把当前剪贴板保存到 Shelf。”
- “显示今天下一个日程。”
- “打开刚才的 Codex 任务。”

### 隐私硬约束

- 默认不需要 API key，不上传剪贴板、日历、音乐或会话内容。
- 每次远程调用前，界面显示处理位置和发送内容范围。
- 不把历史命令和敏感内容写入项目日志。
- AI 失败时必须回退为可解释的本地命令失败，不伪造执行结果。

## 7. 功能路线

> 本节已被[2026-11 全局规划](GLOBAL_PLAN_2026-11.md)第 6 节路线图取代。

### P0：独立可用性（下一开发周期）

- 活动中心成为无音乐时的默认入口。
- 计时器支持开始、暂停、继续、重置、加时、完成后恢复。
- 日历/提醒活动可以独立工作并明确授权状态。
- 增加三个低风险快捷动作：打开常用 App、截图并复制、快速笔记。
- 所有功能独立开关；关闭汽水后不隐藏、不阻塞、不拉起外部窗口。
- 删除或修正所有“后台自动恢复汽水”的旧文案和分支。

### P1：统一活动引擎与 AI Command Bar

- 抽象 `IslandActivitySource` 和统一仲裁器。
- 将计时器、EventKit、音乐适配器迁移到活动源模型。
- 加入活动健康状态、降级呈现、恢复策略和动作列表。
- App Intents / Shortcuts 暴露顶屿本地动作。
- 加入本地命令解析器；先不接云模型。
- 引入命令执行记录的匿名结果分类（成功/拒绝/权限缺失/不可用），不记录原文。

### P2：选择性扩展

- 开发者模式：Codex、Claude Code、Cursor 状态、等待批准、问题回答、任务完成、终端/IDE 跳转。
- 系统 HUD：音量、亮度、Focus、录屏状态、隐私指示器。
- 下载、AirDrop、文件 Shelf。
- 本地 Ollama 或用户自配兼容端点。

## 8. 权限与隐私分级

| 功能 | 权限 | 策略 |
| --- | --- | --- |
| 活动中心、计时器、打开 App | 无额外权限 | 默认可用 |
| 日历、提醒 | 日历/提醒事项 | 用户首次启用时申请 |
| 汽水/网易云控制 | 辅助功能 | 只在启用控制时申请；状态读取失败仍保留基座 |
| Apple Music 控制 | 自动化 | 仅启用 Apple Music 适配时申请 |
| 截图/窗口预览 | 屏幕录制 | P0 不默认启用，按功能申请 |
| 全局快捷键/Caps Lock 等 | 输入监控 | P2，默认关闭 |
| 相机镜像 | 相机 | P2，用户主动打开才申请 |
| 远程 AI | 网络和用户配置端点 | 默认关闭，明确显示数据流向 |

不做“启动即索取全部权限”的首次启动流程。设置页要能逐项查看、关闭和重新授权。

## 9. 验收指标

### 用户体验指标

- 汽水未运行或窗口关闭时，活动中心仍能在一次点击内打开并完成计时器操作。
- 用户关闭汽水后，连续 10 分钟状态刷新不重新打开、取消隐藏或激活汽水。
- 汽水控制失败时，不出现看似可点击但无效的黑色播放/暂停按钮。
- 活动源切换后，恢复到上一个有效活动的成功率达到 100%（测试场景内）。
- 顶屿展开/收起不出现黑边、窗口漂移或两个窗口叠加；减少动效设置下仍可操作。
- 其他 App 进入原生全屏视频后，顶屿不可见且不拦截视频交互；退出全屏后恢复原来的活动状态。

### 工程指标

- `swift test` 覆盖：关闭汽水、窗口关闭、控件树不可用、用户恢复、取消恢复、恢复超时。
- 每个活动源有独立的健康状态测试，不依赖真实外部 App 才能通过单元测试。
- 后台状态刷新不得调用 `NSWorkspace.openApplication`；建立可搜索的日志断言。
- 2 小时长运行无持续增长的任务、观察者、窗口或子进程。
- AI 本地命令执行结果可重放；远程端点未配置时测试不得联网。

## 10. 实施顺序与回滚

1. 先补齐“汽水关闭后基座可用”和恢复契约测试。
2. 再把活动中心和计时器迁移到统一活动源接口，保持现有 UI 外观不变。
3. 增加系统状态和快捷动作，完成无音乐验收矩阵。
4. 加入本地 AI Command Bar，默认只执行固定命令。
5. 经过独立权限和隐私验收后，才评估 P2 开发者模式或 HUD。

每一步都保持可回滚：活动源通过开关注册；新源异常时只移除该源，不回退或重启整个顶屿。外部 App 的打开操作集中在用户动作处理器，禁止散落在定时器、状态刷新和观察者回调中。

## 11. 暂不做

- 不同时实现音乐、AI、文件 Shelf、HUD、通知镜像和 Agent 全部方向。
- 不读取所有第三方通知，不做通知数据库聚合。
- 不默认开启屏幕录制、输入监控、相机或网络权限。
- 不默认接入云端模型，不在代码或文档中保存 API key。
- 不把完整聊天界面放进顶部岛。
- 不以“支持更多音乐 App”作为 0.2 的主要成功标准。

## 12. 会话安全策略说明

旧任务 `01a0a9b3-3bb8-7ac1-a355-cde69d4bef69` 的记录显示一次明确的上游失败：`403 Forbidden`，并附带“该会话已被网络安全策略屏蔽，请开启新会话”。这是会话/网络策略层的拦截证据，不是对当前仓库代码完成了安全漏洞判定，也没有证据表明本地项目被扫描为恶意代码。

后续遇到相同情况：保留错误原文和时间，切换新任务继续；不要为了绕过策略去改代理、关闭安全软件或把项目内容上传到第三方。代码安全问题仍应通过本地审查、测试和明确的安全扫描流程单独判断。

# 顶屿 build 117 歌词稳定性修正版

116 的布局和展开策略已经安装，但真实日志发现汽水 AX 歌词树在渲染器切换时会短暂返回空节点。116 的 0.9 秒新鲜窗口过短，导致同一首歌的歌词在短暂读取失败后被清空，再读到时重新出现。本轮将 `QishuiLyricFreshnessPolicy.maximumAge` 调整为 2 秒：同一进程、同一标题与歌手、已经通过语料门禁的当前句在短暂 AX 空窗期内保持；换歌或身份不一致仍立即拒绝旧歌词。

- 安装目标：`/Applications/顶屿.app`，CFBundleVersion **117**，签名核验通过。
- 300 项 Swift 测试通过；新鲜窗口边界回归测试更新为 2.0 / 2.001 秒。
- 真实调试证据：`.build/qa/build116-live-lyric-debug.log`。其中记录了汽水当前窗口被最小化时 AX 明确返回 `canReadMain=false`，这类状态不会伪造歌词；本轮只对已成功读到的当前句增加短暂空窗容错。
- 当前正常进程已恢复为 `/Applications/顶屿.app/Contents/MacOS/MacBookIsland`，不是 `--preview-*` 预览进程。

这不是把旧歌词无限期保留：2 秒之后仍读不到，歌词会按真实数据状态收起；换歌时身份门禁优先于容错窗口。

# 顶屿 build 116 交互与歌词布局验收

本轮针对两个回归点做了收口：

- **展开触发**：状态/歌词更新不再读取旧的 `NSEvent.mouseLocation` 来合成悬浮进入。只有真实 `mouseMoved` 事件才会触发悬浮展开，因此后台播放、歌词刷新或曲目切换不会在鼠标未移动时自行展开。
- **策略切换**：新增“歌词更新时自动展开”偏好，默认关闭。关闭时保持紧凑态，仍可通过悬浮或点击手动展开；打开时才允许歌词快照到达后自动进入歌词阅读布局。显式打开“显示歌词”仍属于用户操作，会按原逻辑进入展开态。
- **歌词布局**：歌词栏从 340 pt 增至 420 pt，分隔间距从 28 pt 收紧至 24 pt；左侧 202 pt 封面与播放轨道保持稳定。移除下一句显示及其辅助功能描述，只保留当前句和翻译，避免歌词阅读区被第二行抢占。

状态：**表面选定方向 A（2026-11-14 决定）；展开音乐的三行布局试用后被否决，恢复为左侧封面与控制、右侧大歌词的原构图**；紧凑歌词行待定。D0、D1 在代码中，尚未实机验收。本文替换 [全局规划](../product/GLOBAL_PLAN_2026-11.md) 第 3.6 节“视觉”部分的做法：3.6 原先只把现有数值搬进主题层，不改外观；本文给出一套新的视觉与布局。3.1–3.5 的交互规则、切歌过渡、控制不可用四态、首次引导继续有效，并在这里给出具体画面。

可视化稿（各状态 1:1 尺寸示意）：见本文末“示意稿”一节。

## 0. 一句话

**岛就是刘海本身，不是贴在刘海下面的一块玻璃。** 全部状态用同一块纯黑表面、同一套字号和间距；展开面板宽度固定，不因有没有歌词而变形；封面主色只做点缀和氛围光，不做底色。

## 2. 方向

### 方向 A：刘海延伸（已选定）

- **表面**：所有状态、所有活动统一 `#000` 不透明，连续圆角。顶部与屏幕边缘齐平，只圆下角。没有描边、没有投影（菜单栏背景本身就把黑色托住了）。
- **氛围光**：展开音乐时，在封面后方加一层封面主色的径向渐变（不透明度 0.22，半径约 260pt），像封面在黑玻璃里的反光。切歌时随主色 240ms 过渡。这是唯一的“颜色面积”。
- **好处**：岛与刘海是一个物体；降低透明度、增强对比度不需要第二套外观；截图、录屏在任何桌面背景下都一致；不再依赖 `NSVisualEffectView`，展开动画少一层合成〔推断：未测量〕。
- **代价**：放弃 build 112 选定的玻璃质感（当时参考了一份用户选的 Canva 稿）。所以这是需要你拍板的一点。

### 方向 B：精修玻璃（未采用）

保留音乐面板的玻璃，但修掉不一致：头部与展开体都用同一种玻璃（黑叠层提到 0.55，看起来更接近刘海），计时与通知也改成同一种玻璃，描边统一 0.5pt 白 0.10。其余（第 3 节以后的布局、令牌、状态）与 A 完全相同。

两个方向只差“表面”这一层令牌，布局和组件是同一套，可以用一个设置开关在实机上并排比较后再定。

## 3. 设计令牌（`IslandTheme`）

一次定义，所有视图只引用名字。数值是新的，不是现有数值的搬运。

**间距**（4pt 网格）：`xs 4`、`s 8`、`m 12`、`l 16`、`xl 20`。面板内边距统一 `l 16`。

**字号**（系统字体，中文自动落到苹方；时间与数字用 `.rounded` + 等宽数字）：

| 令牌 | 字号 / 字重 | 用途 |
| --- | --- | --- |
| `caption` | 11 medium | 时间读数、来源、状态说明 |
| `body` | 13 regular | 歌手、通知正文、下一句歌词 |
| `title` | 15 semibold | 歌名、通知标题、计时状态 |
| `lyric` | 21 semibold | 当前歌词（行高 26） |
| `display` | 28 semibold rounded | 计时数字 |

从约 10 档收成 5 档。紧凑态和折叠态只用 `caption` 与 12pt 的 `compactTitle` 一个例外。

**文字不透明度**（白）：`primary 0.96`、`secondary 0.62`、`tertiary 0.40`、`disabled 0.24`。从 9 档收成 4 档。

**填充**（白）：`fill 0.08`、`fillHover 0.14`、`fillPressed 0.20`；分隔线 `separator 0.10`。

**圆角**（全部连续圆角）：展开面板下角 `28`，内部卡片与按钮胶囊 `14`，封面 `size × 0.22`，紧凑与折叠态的下角 = 带高 / 2。

**强调色**：沿用现有的封面主色提取（12 段色相直方图 + 对黑底对比度归一化），新增一条约束——用于填充的强调色与黑底对比度至少 3:1，用于文字的至少 4.5:1；不满足时提亮，提不上去就退回白 0.86。强调色只用在：进度填充、逐字高亮、折叠态声波、氛围光。

**动画**：

| 令牌 | 值 | 说明 |
| --- | --- | --- |
| `expand` | 240ms，(0.20, 0.85, 0.25, 1.0) | 不变 |
| `collapse` | 180ms，(0.40, 0, 0.20, 1.0) | 不变 |
| `content` | 内容在框体动画开始后 60ms 淡入，120ms | 替代现在从 y 0.025 放大的做法，文字不再被压扁 |
| `lyricLine` | 换句 180ms：旧句上移 6pt 淡出，新句从下 6pt 淡入 | 减少动态效果下只淡入淡出，100ms |
| `swap` | 切歌换入 160ms 交叉淡化 | 原子发布之后才发生 |
| `accent` | 主色与氛围光 240ms | 现为 200–240ms，统一 |

## 4. 各状态布局

以默认刘海宽 185 为例；实际宽度仍按 `IslandDisplayGeometry` 的刘海实测值计算。

### 4.1 折叠（带高 33）

- 两翼从 22 加宽到 **28**。左翼：封面 18pt。右翼：三根强调色声波（播放）；暂停时三根压成三个点，静止，`secondary`。不再用暂停图标——“压扁的声波”比图标更安静，也更好认出是同一个东西的两种状态。
- **切换中**：封面降到 0.4 不透明度，声波换成同色的三点依次明暗（减少动态效果下静止）。
- 计时：左翼计时图标，右翼剩余分钟数 `caption` 等宽数字，翼宽按内容到 40。
- 总宽 185 + 56 = 241。

### 4.2 紧凑（悬停预览，带高 33）

把紧凑态从“缩小的歌名歌手”改成**歌词行**：

- 左翼 **固定 132**：封面 22 + 当前歌词一行（12 semibold，超长时用现有跑马灯参数滚动）；没有歌词或歌词关闭时显示“歌名 · 歌手”。
- 右翼 **固定 132**：剩余时间 `-1:42`（caption，等宽）+ 声波。
- 总宽 185 + 264 = 449，**不随内容变化**。

依据：代码里已有“紧凑歌词”布局（`MusicCompactLayout` 的歌词翼宽），build 144 时是一个可选项，之后被固定关闭（`IslandModel.compactWidth` 传 `hasCurrentLyric: false`）。固定关闭发生在 build 146 的提交里（`cc9a5a3`），提交说明与更新记录都没有写原因；而 [歌词产品方案](../product/LYRICS_PRODUCT_PLAN.md) 第 2 节至今仍要求“紧凑态显示当前句”。**实现前仍需你确认当初关掉它的理由**；本方案用固定翼宽，避开最可能的原因（随歌词长短伸缩）〔推断〕。

### 4.3 展开 · 音乐（宽固定 560）

```
┌──────────────────────── 33pt 摄像头带（纯黑，无内容）────────────────────────┐
│  ┌──────┐  歌名（title，单行，超长滚动）            ⏮   ⏯   ⏭      ⋯         │
│  │ 封面 │  歌手（body / secondary）                 32   38   32     24        │
│  │  56  │  汽水音乐 ·（caption / tertiary，来源）                               │
│  └──────┘                                                                   │
│  ▍当前歌词（lyric 21，逐字高亮用强调色）                                       │
│    下一句（body / tertiary）                                                 │
│  1:02 ━━━━━━━━━━━━━━━━━━━━━━━━━━○──────────────────────────────── -2:43      │
└──────────────────────────────────────────────────────────────────────────────┘
```

- **尺寸**：开歌词 560 × (33 + 166) = 560×199；关歌词 560 × (33 + 108) = 560×141。宽度永远 560。
- 高度只由**用户的“显示歌词”设置**决定，不由“这首歌有没有歌词”决定：开着歌词但这首没有时，歌词区显示 `tertiary` 的“纯音乐，请欣赏”或“暂无可核验的歌词”，高度不变。
- 歌名从 118pt 的窄列解放到约 300pt 的整行，单行加跑马灯，不再两行截断。
- 控制按钮在第一行右侧：上一首 / 下一首 32pt 圆（`fill`），播放 / 暂停 38pt 白圆黑图标。点击热区都至少 36pt。
- 右上角四个按钮合并成一个 `⋯` 菜单：显示歌词、展开方式（悬停 / 点击 / 保持）、最小化、收起。收起仍然可以点岛外部完成（保持展开模式下用菜单里的“收起”）。
- 进度行：全宽 4pt 细条，悬停或拖动时变 6pt 并出现 10pt 圆钮；两端是已播放与剩余时间（`caption`，等宽）。只在 `canSeek` 时可拖，规则不变。
- 歌词区：左侧 3pt 强调色竖条 + 当前句；下一句 `body / tertiary`；翻译行（有时）替代下一句的位置，不增加高度。

对照现状：最常见的“开歌词”状态从 694×177 变成 560×199——窄了 134pt，高了 22pt；歌词可用宽度从 446 增加到 528。

### 4.4 切歌中（规划 3.2 的画面）

收到被暂缓的切歌候选时：

- 旧封面、歌名、歌手整体降到 0.45 不透明度，保持原内容；
- 进度条冻结，圆钮隐藏，时间读数换成 `caption / tertiary` 的“切换中”；
- 歌词区清空，只留竖条，竖条做一次 600ms 的呼吸（减少动态效果下静止）；
- 完整候选发布后，用 `swap` 160ms 一次性换入新封面、歌名、歌手、时长和氛围光颜色。

不显示任何新歌字段，原子发布规则不变。按规划要求，先用 `DailyUsageAnalyzer` 确认“早期候选之后未切歌”比例接近 0 再开启。

### 4.5 控制不可用四态（规划 3.3 的画面）

控制区位置固定（第一行右侧，约 118×38），四种原因在**同一个位置**呈现，面板不变形：

| 原因 | 控制区显示 | 来源行（歌手下面那行） |
| --- | --- | --- |
| 权限缺失 | 一个 `fill` 胶囊按钮“授权辅助功能 ›”，可点，打开系统设置 | “汽水音乐 · 需要辅助功能权限” |
| 控件树暂不可用 | 三个按钮 `disabled` + 胶囊左侧小转圈 | “汽水音乐 · 正在重新连接” |
| 主窗口已关闭 | 三个按钮 `disabled` | “汽水音乐 · 窗口已关闭，重新显示后恢复” |
| 需要用户恢复 | 一个白色胶囊按钮“重启并连接”，只在用户点击时执行 | “汽水音乐 · 需要重启汽水以连接控制” |

说明文字放在来源行而不是另起一行，所以四态与正常态高度一致。媒体键归属提示按规划 3.4 只在设置里出现，不上岛。

### 4.6 计时、通知、活动中心

同一块黑色表面、同一套令牌，宽度统一 **460**（现在是 `max(刘海+140, 420)`，随刘海变）：

- **计时**：左侧 56pt 进度环（4pt，强调色取固定的计时绿），中间 `display` 数字 + `body / secondary` 状态，右侧 暂停 / 重置 / +1 分钟三个 32pt 圆按钮。高 33 + 96。
- **通知**：40pt 应用图标，`title` 标题 + 两行 `body` 正文，右侧“打开”（白胶囊）与“关闭”（`fill` 胶囊），胶囊高 28。高 33 + 96。
- **活动中心**：2×2 卡片网格——专注计时（四个预设）、音乐恢复（有时）、日历、提醒事项。卡片 `fill`、圆角 14。高随卡片行数。
- **仲裁可见性**：通知打断计时或音乐时，折叠态右翼出现 6pt 的白点（未读），展开后消失。现在唯一的提示“N 条提醒”只在计时头部，太隐蔽。

## 5. 辅助功能（随新视图一起做，不再单列）

- 每个按钮有标签与状态；播放键朗读“播放”或“暂停”和当前歌名。
- 进度条是可调节元素，朗读“已播放 1 分 2 秒，共 3 分 45 秒”；可调节动作每次 ±10 秒，只在 `canSeek` 时提供。
- 朗读顺序：歌名 → 歌手 → 控制 → 进度 → 歌词。歌词作为普通文本，不逐句播报。
- **增强对比度**：`secondary` 0.62 → 0.82，`tertiary` 0.40 → 0.64，按钮 `fill` 加 1pt 白 0.30 描边，氛围光关闭。
- **降低透明度**：方向 A 无需改动；方向 B 退回方向 A 的纯黑。
- **减少动态效果**：沿用现有的 0 秒框体变化；歌词换句、切换中呼吸、声波全部静止或只淡入淡出。

## 6. 设置与首次引导

- 设置窗口保留四页（常规、音乐、活动、关于），布局页并入“常规 → 位置与尺寸”，草图编辑器移到按住 Option 才显示的开发者区。
- 音乐页顺序：播放器（三个应用的开关与状态灯）→ 歌词（开关 + 网络说明原地展开）→ 面板（展开方式）→ 诊断（默认折叠，含媒体键归属）。
- 首次引导按规划 3.5 的三步，窗口 480×360，每步一屏：选播放器 → 只申请该播放器需要的权限 → 实时预览岛上出现当前歌曲。每步都有“跳过”。

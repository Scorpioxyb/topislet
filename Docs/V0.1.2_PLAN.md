# v0.1.2 稳定化计划

目标版本：`v0.1.2-alpha.4`

App 版本：`0.1.2 (22)`

发布方式：GitHub DMG 开发预览版，继续使用 ad-hoc 签名；Apple Developer 签名和公证不阻塞本版本。

## 版本目标

v0.1.2 不扩展新的音乐应用、计时器、通知或歌词。版本只处理汽水音乐、Apple Music、网易云音乐和岛基础交互的日常稳定性。

## P0

- 三来源前台切换、播放优先级、退出回退和控制代次全部通过自动化与实机交叉验证。
- 汽水可见、最小化、关闭、重启和 AX 控件树异常时不弹窗、不抢前台、不误控其他媒体。
- 播放 / 暂停后进度不回退，暂停确认后冻结，恢复播放后从可信锚点继续。
- 切歌时歌名、歌手、专辑、封面和时间线原子收敛，不显示新旧混合快照。
- 抖音、QuickTime、Safari 和 Chrome 占用系统媒体焦点时，三项控制仍只命中当前已适配来源。
- 悬停、点击、连续反向展开和内容切换不产生水平漂移、重复形变或明显主线程停顿。

## P1

- 设置面板补齐开机启动、显示控制、重置布局和权限恢复入口。
- 内置屏、外接屏和显示排列变化后无需重启，岛重新锚定目标屏幕。
- 跟随系统“减少动态效果”设置，关键状态反馈仍可识别。
- 完成两小时播放、频繁切歌和来源切换长稳测试。

| Apple Music 电台封面 | P95 不超过 1.5s |

| 窗口中心漂移 | 不超过 0.5pt |
| 空闲 CPU | 通常不超过 2%，不得持续 30 秒高于 5% |
| 两小时内存增长 | 不超过启动稳定基线 15% |
| 遗留状态流子进程 | 0 个 |

## 阶段

1. M0：冻结范围，建立版本、测试和发布基线。
2. M1：关闭三来源切换、汽水后台控制、进度和元数据 P0。
3. M2：完成动画终验、设置产品化和权限恢复。
4. M3：完成多显示器、减少动态效果和两小时长稳。
5. M4：生成 DMG、SHA-256、发布说明并通过 GitHub CI。

## 明确不做

- QQ 音乐、Spotify 和其他新音乐应用。
- 汽水定向 seek，除非出现可验证且不会误控系统当前媒体的接口。
- 歌词来源扩展。
- 计时器、日历、提醒事项和第三方消息通知扩展。
- Windows 版本。
- 大规模拆分 `main.swift`；仅允许为当前 P0 降低风险的小范围提取。

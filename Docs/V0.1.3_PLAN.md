# v0.1.3 日常体验优化计划

目标版本：`v0.1.3-dev`

App 版本：`0.1.3 (24)`

发布方式：GitHub DMG 开发预览版，继续使用 ad-hoc 签名；开发阶段不创建 Tag、不推送 GitHub Release。

## 版本目标

v0.1.3 先用真实日常日志识别和修复现有音乐体验问题，不扩展新的音乐应用、计时器、通知或歌词。汽水音乐继续作为主适配，Apple Music 与网易云音乐维持现有 Alpha 边界。

## P0

- 每个已接受的 seek 最终进入确认、超时或取消之一；连续拖动覆盖、切歌、来源切换、播放器退出和 App 停止均留下结构化原因。
- 正常 seek 取消不算异常，但计入样本终态覆盖；已接受 seek 缺少任何终态时日报必须保持 `partial`。
- 日报继续只记录来源标签、匿名延迟、目标千分比和取消原因，不记录歌名、歌手、歌词、封面、账户或文件路径。
- 不增加媒体轮询，不改变来源仲裁、PID 定向控制、汽水 seek 安全门禁或岛内进度条行为。

## 后续 P0 候选

完成首个可观测性修复并积累新的日常样本后，只对真实越线项排期：

- 切歌文本、歌手与封面原子收敛延迟。
- 播放 / 暂停权威确认延迟和进度冻结一致性。
- seek 确认延迟、超时率以及非预期取消比例。
- 来源切换抖动、退出回退和多媒体并存误控。

## 质量门禁

| 指标 | 门槛 |
| --- | --- |
| 已接受 seek 终态覆盖 | 100% 进入确认、超时或取消 |
| 无终态 seek | 0 个；否则样本状态为 `partial` |
| 正常取消误报异常 | 0 个 |
| 新增媒体轮询 | 0 |
| 原始媒体元数据写入日志 | 0 |
| 自动化回归 | 全部通过 |
| Release 安装 | 单一主进程、两个预期只读状态流、严格签名通过 |

## 阶段

1. M0（完成）：审计最近 24 小时真实日志，冻结范围和首个 P0。
2. M1（完成）：补齐 seek 取消终态、原因聚合和日报 schema 4。
3. M2（完成）：安装 Release build 24；20/20 个真实 seek 具备终态，确认 9、超时 0、正常覆盖取消 11，样本完整且无异常。
4. M3：依据真实 P50/P95 和异常数据选择下一项 P0，不凭主观猜测扩大改动。
5. M4：完成候选门禁后生成 DMG、SHA-256 和发布说明，经产品负责人确认后再创建 Tag 与推送。

## 明确不做

- 新音乐应用适配。
- 计时器、日历、提醒事项和第三方消息通知扩展。
- 歌词来源扩展。
- Windows 版本。
- 大规模拆分 `main.swift` 或重写媒体底层。

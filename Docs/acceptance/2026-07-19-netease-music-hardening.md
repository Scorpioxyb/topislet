# 网易云音乐后台同步与进程重绑验收

日期：2026-07-19

## 环境

- 设备：MacBook Air (`Mac17,4`)，Apple M5，24 GB
- 系统：macOS 26.5.2 (`25F84`)
- 网易云音乐：3.1.8 (`3368`)
- Bundle ID：`com.netease.163music`
- 顶屿：0.1.1 (`18`)

## 本轮问题

- 顶屿先启动、网易云后启动时，长期 `stream-client` 可能在网易云 PID 出现前建立，首次定向读取可以显示歌曲，但后续后台切歌可能漏报。
- 网易云重启后的首次播放会短暂返回迟到的 `paused` 快照；若播放事件发生在状态流重绑前，岛可能继续保留 Apple Music。
- 状态流漏报后，原协调器没有网易云专属自愈读取，重新激活网易云才会刷新。

## 已通过

- 网易云新进程出现后，先通过 Bundle ID 与当前 PID 取得有效快照，再重建专属状态流；旧 PID 的订阅进程不再继续承担新会话。
- 网易云已运行但尚无有效曲目时继续执行低频 PID 定向发现，不依赖它先成为当前显示来源，避免来源选择死锁。
- 新 PID 首次有效曲目进入 5 秒有界收敛窗口，并在状态流重绑后按 `200ms / 500ms / 1s` 做短确认；迟到 `paused` 最终收敛为真实 `playing`。
- 正常稳态仍以专属状态流为主；当前网易云来源每秒最多一次轻量时间线校验，只有发现歌曲身份变化时才读取封面并执行原子确认。
- 同专辑、同封面的 Rammstein 样本已覆盖：`Engel`、`Du hast` 等曲目共用 `8386 bytes` 封面时，歌名、歌手、时长和封面作为完整快照提交。
- 不同封面切歌完整快照实测约 `0.783s`；后台同封面变化不再需要前置或重新激活网易云才能恢复。
- 实机重启日志确认：顶屿 PID `45597` 运行期间，网易云新 PID `45994` 被识别；同一曲目状态从 `paused` 收敛为 `playing`，来源切换日志同步完成。
- Chrome YouTube 视频显示 `Pause (k)` 时，分别暂停和恢复网易云 PID `45994`，Chrome 两次均保持播放；控制仍只走网易云进程内原生“控制”菜单。
- 新增后台同封面漏报恢复、运行未选中时首次曲目发现、重绑期间首次播放竞态回归；`swift test` 共 134 项通过。
- `swift build -c release`、`Scripts/package-app.sh` 和 `/Applications/顶屿.app` 严格签名验证通过。

## 仍有限制

- 网易云尚无经过来源证明的定向 seek，进度条继续保持只读。
- 状态流和来源切换系统日志只记录曲目身份、PID、播放态与来源标签，不记录封面内容或用户数据。

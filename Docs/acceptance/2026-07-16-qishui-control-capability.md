# 2026-07-16 汽水控制能力动态验收

## 目标

验证汽水主窗口生命周期变化时，顶屿自动更新播放 / 暂停、上一首和下一首的可用状态，不依赖用户手动同步，也不把命令转发给系统当前媒体。

## 环境

- 顶屿：当前 `codex/qishui-control-capability` 本机安装版。
- 汽水音乐：`com.soda.music`，唯一标准窗口。
- 辅助功能：已授权。
- 前台应用：Codex，bundle identifier 为 `com.openai.codex`。
- 状态来源：汽水专属 MediaRemote stream；控制路径：汽水 PID 内唯一语义 AX 控件。

## 动态结果

1. 汽水窗口可见时，设置“音乐 - 当前活动”的“可用控制”显示“播放暂停、上一首、下一首”。
2. 完全关闭汽水主窗口后，约 1.2 秒内三项控制自动禁用，原因显示“汽水主窗口已关闭；请先显示或最小化汽水窗口。”
3. 无窗口期间歌曲、封面和进度仍由汽水专属 stream 更新；顶屿不发送系统媒体键，不自动激活或重开汽水。
4. 重新显示汽水主窗口后，约 1.2 秒内三项控制自动恢复。
5. 最小化唯一汽水窗口后，三项控制继续保持可用；播放 / 暂停命中汽水语义控件，最终播放状态成功切换。
6. 控制完成后汽水窗口仍为 `AXMinimized=true`，前台仍为 `com.openai.codex`，没有移动鼠标。
7. 恢复测试前播放状态后，安装版 `--adapter-status` 返回 `isPlaying=true`、`verifiedQishuiSource=true`、非空封面和 `sourceBundleIdentifier=com.soda.music`。
8. 额外异常注入中，汽水可见主窗口仍存在，但 Electron 暂时返回 `AXWindows=count:1,roles:AXApplication`；新判定保持为未知而不是窗口关闭，语义控制在无法唯一验证控件时安全失败。Electron 重新暴露正常树后，诊断恢复到 306 个节点和唯一候选，暂停与恢复播放再次实测成功。

## 自动回归

- 新增控制能力决策测试：未运行、未授权、AX 读取暂时失败、无窗口和存在窗口分别映射到明确状态。
- 只有明确不可控制状态会禁用按钮；一次 AX 读取失败保持严格语义控件校验能力。
- `AXWindows` 非空但 Electron 暂时把窗口暴露为非标准角色时判定为未知，不冒充“窗口已关闭”，并继续进入既有有界重扫。
- 若非标准 AX 树在有界重扫后仍未恢复，控制安全失败并提示辅助功能树暂不可用，不改投系统媒体。
- 控制执行前再次探测窗口能力，防止迟到 AX 通知或旧界面状态创建错误的乐观播放状态。

## 结论

汽水主窗口关闭、恢复和最小化三种状态的控制能力自动切换通过。当前无窗口控制仍受汽水上游能力限制，但产品会明确禁用，不会误控其他媒体。

边界调查期间临时使用 Computer Use 读取汽水 Electron 窗口，并对明确的中央播放图标执行一次点击以恢复重启前播放状态；完成后已执行 `js_reset`，Codex 已恢复前台，没有遗留控制会话。该操作不属于顶屿产品路径。

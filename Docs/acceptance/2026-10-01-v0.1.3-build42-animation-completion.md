# v0.1.3 build 42 动画收尾回归

日期：2026-10-01

版本：Release 安装版 `/Applications/顶屿.app`，CFBundleVersion `42`。

## 问题与修正

build 41 的窗口动画在 AppKit completion 外，还会在动画时长加 50ms 后调用收尾方法；接受最新代次后再次设置窗口与内容 frame。该实现与 QA 要求的 completion 收尾和正常完成不再 snap 不一致。

build 42 删除延迟收尾，动画 completion 只通过既有代次/目标模式门禁清除进行中标记，不再写入最终几何。即时模式与减少动态效果的直接落位保持原实现。没有新增替代计时器，也没有修改系统动画曲线。

- 缺失窗口采样 `0`，最大窗口数量 `1`；

## 音乐控制补充回归

同日对 build 42 执行实际 Computer Use 点击：

- 汽水窗口可见时，顶屿暂停键使语义变为“播放”；下一首由 `float 2.0` 切到 `Bloody Paradise`，上一首返回 `float 2.0`。
- 单独读取窗口属性发现，最小化后立即重新读取汽水的 Computer Use 状态不能保持可验证的后台状态。改用 `Command-M` 后仅观察顶屿，以独立只读 AX 属性确认 `AXMinimized=true`。此状态下顶屿播放键语义变为“暂停”，下一首与上一首完成同一对歌曲的往返切换，暂停键再变为“播放”；再次独立读取仍为 `AXMinimized=true`。控制可用性为 `available / allowsControl=true`。
- 关闭汽水主窗口后，其 PID `27679` 仍运行、AX 窗口数为 `0`，控制可用性为 `windowClosed / allowsControl=false`；顶屿显示“重启并连接汽水音乐播放控制”。5 秒、32 次只读观察中窗口数始终为 `0`，没有自动拉起。
- 实际点击该恢复入口后，汽水变为新 PID `27893`；但随后诊断仍为 `controlTreeUnavailable / scanned=2 / candidateCount=0 / manualAccessibilityEnabled=true`。继续检查活动入口时 Computer Use 报告 Mac 已锁屏。此恢复流程未验证成功，不能沿用 build 41 的恢复成功记录替代。
- 本轮汽水原先未运行，锁屏后对已核对路径的新测试 PID 发出受控终止，后续进程检查确认汽水主进程消失，恢复原先停止状态。

# P0 三音乐来源状态一致性验收

日期：2026-07-20

## 范围

- 保持新增音乐应用适配冻结，只检查汽水音乐、Apple Music 和网易云音乐。
- 审计切歌、播放暂停、应用退出、前台来源切换和控制目标绑定。
- 不修改各播放器的专属读取协议，不恢复系统全局媒体控制。

## 发现与修复

1. 控制入口原先只根据岛上歌曲携带的 Bundle ID 选择适配器，没有再次核对来源状态机的当前选择。
2. 汽水控制执行前需要异步检查辅助功能控件树；检查期间来源若切走，旧请求缺少选择代次门禁。
3. 来源切换时，上一来源的切歌反馈和控制后刷新 burst 会短暂保留到新来源。

修复后：

- 控制授权同时绑定显示来源、状态机当前来源和选择代次。
- 汽水在排队切歌同步和控件树检查后重新验证授权；来源切走再切回也不会复用旧授权。
- 音乐来源 Bundle ID 变化时，立即取消上一来源的切歌反馈、刷新 burst、待处理进度和拖动状态。
- 同一来源内切歌不会被误判为跨来源切换，原有切歌反馈保持。

## 待人工确认

验收时系统处于登录窗口前台。为避免强制激活播放器或改变用户播放状态，本批没有自动操作 Apple Music 与网易云。解锁后仍需连续执行以下视觉确认：

1. 汽水、Apple Music、网易云依次前台切换，岛的歌曲、封面、播放按钮和进度必须原子切换。
2. 切歌反馈未结束时切到另一播放器，新来源不得保留上一来源的按钮反馈。
3. 播放暂停请求发出后立即切换播放器，旧请求不得改变新来源的岛状态。
4. 完整退出当前播放器，岛应立即回退到仍可用的来源；无来源时恢复默认样式。

## 结论

状态机、控制授权和当前汽水 Release 会话已通过自动化门禁。三播放器交叉视觉实测尚未完成，因此本项保持“自动化已验收 / 待三应用交叉实测”，不提前标记为全面验收。

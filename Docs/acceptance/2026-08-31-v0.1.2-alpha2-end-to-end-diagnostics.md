# v0.1.2-alpha.2 端到端媒体诊断验收

日期：2026-08-31

## 目标

- 将按钮派发延迟与用户看到的 UI 反馈延迟分开。
- 记录汽水和 Apple Music 播放状态的权威确认，不把乐观 UI 当成真实播放器确认。
- 只有进度进入目标容差并连续稳定 350ms，才把 seek 记为真实收敛。
- 复用现有状态机和刷新 burst，不增加媒体轮询或控制命令。

## 实现

- `control_issued` 增加目标播放态；`ui_published` 用于计算点击到 UI 的延迟。
- 汽水从 PID 匹配的 MediaRemote 新样本或 AX 进度推断记录 `playback_confirmed`；4 秒未确认记录超时。
- Apple Music 从绑定当前实例与曲目的 Apple Event 快照记录 `playback_confirmed`；1.2 秒 expectation 未收敛记录超时。
- UI 原有 pending seek 稳定门禁记录 `seek_confirmed`；3.5 秒未收敛记录超时。
- 日报 schema 升级到 2，继续兼容 alpha.1 的 schema 1 事件。

## 边界

当前没有主动启动或操作任何播放器，因此本轮只证明采集、聚合、版本兼容和安装链路通过。播放 / 暂停、切歌和 seek 的 P50/P95 需要由日常真实操作积累，不能用自动播放或伪造事件替代。

# build83 歌词匿名延迟观测

状态：本地 Release 候选，Goal 仍进行中；未封版、未发布。

## 实现

新增 `lyric_ui_published` 结构化事件。事件只包含来源、歌曲匿名指纹、歌词快照匿名指纹、行数、桌面歌词标记和 `lyric_age_ms`，不写入歌名、歌手或歌词文本。快照指纹只有在当前歌曲和当前歌词数组同时匹配时才记录年龄，避免把旧快照误算成新延迟。该事件记录的是“AX 快照到 `MusicState`/UI 模型发布”，不是像素渲染完成时间。

## 当前实机证据

- 安装版本：`/Applications/顶屿.app`，`0.1.3 (83)`。
- `swift test`：289 项通过。
- Release 构建：40 段代码/资源校验通过，严格签名通过。
- 只读汽水观察：不点击、不切歌、不播放/暂停。
- 2026-10-02 09:48-09:53 PDT 捕获 3 条真实 `lyric_ui_published`：年龄为 `351ms`、`504ms`、`504ms`，均为 `line_count=2`、`desktop_snapshot=0`。3 条记录只有 1 个唯一歌词匿名指纹，说明这是同一 active 行的重复发布，不是 3 个不同歌词行。匿名歌词指纹和歌曲指纹未暴露内容。

这些记录证明快照到 UI 模型发布的年龄链路已可观测，当前样本均低于 0.9 秒新鲜度门禁；由于只有 1 个唯一 active 行，不能代表 active 行切换、像素端到端延迟、P95 或完整长时间延迟分布。

## 尚未关闭门禁

- 收集足够多的不同 active lyric 变化，形成 P50/P95 延迟分布。
- 证明 active 行与音频时间轴的对应关系，而不只证明 AX active 行被读取。
- 同一句长歌词的完整滚动往返周期。
- 连续模式切换逐帧黑边/残影，多屏、全屏、Reduce Motion 和两小时性能回归。

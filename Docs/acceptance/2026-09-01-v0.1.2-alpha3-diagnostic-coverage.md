# v0.1.2-alpha.3 日常诊断覆盖验收

日期：2026-09-01

## 目标

- 证明日常日志是否持续采集，而不只在 App 启停时留下事件。
- 将“没有发现异常”和“没有足够真实使用样本”明确分开。
- 不增加媒体状态轮询，不记录歌曲、账号或文件路径明文。

## 实现

- `MusicAdapterCoordinator` 复用现有状态 tick，每 15 分钟写入一次 `observation_heartbeat`。
- 心跳只包含适配来源、是否有当前曲目、播放 / 暂停状态和本次运行时长。
- 日报 schema 3 新增心跳数量与间隔、媒体存在心跳、按来源事件数、媒体活动事件数、缺失样本类型和 `no_media_activity / partial / complete` 覆盖状态。
- 播放确认与 seek 确认存在缺口时，覆盖状态不会标记为完整；异常与样本完整性保持两套独立结论。

## 自动化验证

- 完整 `swift test`：213 项通过，异常 0。
- 日志、聚合与 15 分钟心跳边界契约：8 项通过，异常 0。
- alpha.2 的 8 条真实历史事件由 schema 3 正常解析：来源事件 3 条、媒体活动 0 条、覆盖状态 `no_media_activity`、异常 0。

## 性能与隐私边界

- 心跳由现有 tick 做时间门控，不创建额外 Timer、Task、MediaRemote 请求、AX 扫描或 Apple Event。
- Unified Logging 仍使用结构化白名单字段；歌曲仅在其他事件中使用 12 位截断哈希，不记录歌名、歌手、歌词、封面、账号或用户路径。
- 心跳间隔超过 20 分钟只进入覆盖统计，不直接记为产品异常，因为系统睡眠也可能造成间隔。

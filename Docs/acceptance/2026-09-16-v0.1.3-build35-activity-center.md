# v0.1.3 build 35 空岛活动中心验收

日期：2026-09-16

## 目标

纠正 build 34 将无活动空岛完全禁用点击的产品逻辑。空岛应当是专注计时、日历和提醒事项的入口，但不能恢复空音乐条，也不能因鼠标经过自动弹出完整面板。

## 实现

- 新增独立 `activityCenter` 活动状态。
- 无音乐时点击折叠岛直接展开活动中心；真实音乐存在时仍进入音乐活动。
- 活动中心不参与悬停自动展开，避免鼠标经过摄像头区域时强打扰。
- 活动中心“收起”进入紧凑活动条，“最小化”返回折叠空岛。
- 音乐在提醒展示期间首次出现时不打断提醒，提醒结束后再切换到紧凑音乐岛。
- 首次启动无音乐保持折叠；重复打开 App 不改变已有紧凑或展开状态。
- 音乐来源退出后，即使岛已折叠也会把活动类型恢复为活动中心。

## 自动化

- `swift test --quiet`：235 项通过。
- 覆盖空岛点击路由、活动中心悬停门禁、计时器与提醒路由、提醒结束后的音乐优先级及音乐接管条件。
- `swift build -c release`：通过。

## 边界

本轮不改变音乐元数据、来源仲裁、PID 定向控制、进度跳转或 EventKit 数据范围。活动中心只提供顶屿已有能力的入口，不读取其他 App 的系统通知。

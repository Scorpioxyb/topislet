## 汽水退出场景

通过用户级退出汽水后：

- 汽水主进程消失；
- 顶屿控制状态为 `notRunning / allowsControl=false`；
- 顶屿没有自动重新打开汽水；
- 顶屿回到活动中心，计时、日历和提醒入口仍可用。

测试结束后只通过一次显式恢复把汽水重新启动并放回后台；没有把该恢复行为放入后台轮询逻辑。

## 标准全屏抑制

使用 Safari 新建空白标签页执行原生全屏快捷键，并直接读取 WindowServer 窗口元数据：

- 进入全屏后，Safari 覆盖目标显示器，WindowServer 中不再出现顶屿窗口；
- 退出全屏后，顶屿恢复为一个窗口；
- 没有读取页面内容，也没有打开外部网站。

这证明标准 macOS 全屏路径已通过。百度网盘首页的普通放大窗口实测为 `1710×991`，顶屿保持可见，符合“普通最大化不触发抑制”的边界；百度网盘播放器的应用内伪全屏、桌面 2 组合仍未在本机完成真实回归，不能用本项替代。

2026-09-30 连续 WindowServer 采样还观察到 Safari 全屏窗口由 `1710×1107, y=0` 收敛到 `1710×1073, y=34` 时，顶屿窗口消失；其他桌面上的普通窗口仍不触发覆盖判断。本项仍不能证明百度网盘播放器伪全屏通过。

2026-10-01 继续操作既有 Safari 空白测试窗口时，AX 能访问窗口并执行 Raise，但当前前台应用仍为 Chrome，当前可见窗口列表也没有 Safari，`--fullscreen-status` 为 `hasCoveringWindow=false`。因此本次操作不能作为全屏冷启动或当前桌面全屏验收证据，已请求用户把测试窗口切到当前可见桌面。

## 百度播放器与全屏冷启动补充验收

2026-10-01 检查百度网盘 `CFBundleDocumentTypes`，确认其支持本地 `mp4/mov`。使用 AVFoundation 生成 10 秒、640×360、30fps 的无声移动色块视频，经 Finder 的“打开方式 → 百度网盘”进入 `videoPlay?from=localFilePreview`；没有上传文件、读取私人视频或更改默认播放器。

实际操作与窗口元数据：

1. 普通播放器窗口为 `1080×650, x=315, y=120`，当前前台 Bundle ID 为 `com.baidu.BaiduNetdisk-mac`，顶屿窗口可见。
2. 点击播放器内部右下角全屏入口后，播放器为 `1710×1073, x=0, y=34`；`--fullscreen-status` 为 `hasCoveringWindow=true`，可见窗口列表没有顶屿。
3. 在该全屏状态下，对已核对路径的顶屿 PID `14387` 执行受控 `SIGTERM`，确认进程退出，再通过 Computer Use 打开安装应用。新 PID 为 `19986`，百度仍为前台全屏，顶屿没有可见窗口。Computer Use 绑定超时并不表示启动失败，进程和 WindowServer 已分别核验。
4. 播放结束后 Escape 未退出全屏；执行 `Control-Command-F` 后播放器恢复为 `1080×650`，覆盖判断为 `false`，顶屿恢复一个 `245×35, x=732, y=-1` 窗口。
5. 在 Finder 两次打开已有安装应用，PID 始终为 `19986`；面板仍只有一个，测试打开的设置窗口随后关闭。

本项证明百度播放器内部全屏入口、全屏期间冷启动与退出后恢复可用。由于 `Control-Command-F` 能退出该路径，不能把它另算作独立的伪全屏路径。`Control-Right` 没有产生可验证的桌面切换，Mission Control/Dock 也未提供可操作的 AX 状态，因此不宣称“桌面 2”组合通过。受控进程终止不是菜单正常退出；Command-Q 在本次绑定下未退出应用，该用户路径仍待核验。

测试文件保留在临时目录 `$TMPDIR/topislet-fullscreen.*/topislet-fullscreen-test.mp4`，可在后续桌面 2 验收中复用。独立 Finder 窗口已恢复图标视图并关闭。清理时百度绑定已回到原有主窗口，未对它执行关闭，也不宣称测试播放器的用户级关闭流程通过。

## 展开与折叠窗口

2026-09-30 安装版活动入口与收起按钮实际点击通过，展开与收起稳定态截图未见轮廓外的黑色矩形。新增 `Scripts/verify-island-window-animation.swift --observe-only`，只读取窗口元数据，配合 Computer Use 点击验收。

连续采样发现默认 `-0.5pt` 顶部偏移在中间帧发生 `1pt` 取整漂移；渲染顶边现统一对齐整点，保留原有系统动画曲线。修正后采样不再触发顶边漂移门禁，但观察脚本的完整尺寸门禁尚未关闭：端点选择逻辑已修正，随后的实机重跑被 Mac 锁屏中断。因此不宣称连续动画或折叠黑边最终验收完成。

2026-10-01 解锁后补充结果：

- `swift Scripts/verify-island-window-animation.swift --observe-only` 配合 Computer Use 展开与收起，通过 2,426 帧采样：始终一个窗口，顶边/中心漂移不超过脚本既有 `0.75pt` 阈值，尺寸没有越过 `245×35` 与 `420×211` 端点。
- 另一次 20 秒、5ms 请求间隔的只读 WindowServer 采样覆盖重复展开/收起，共 2,442 帧，水平中心相对屏幕中线的最大误差为 `0.5pt`，顶边漂移为 `0pt`。实际平均采样频率约 `122Hz`，满足 QA 的 `100Hz` 和 `0.5pt` 中心门槛，未放宽阈值。
- 稳定态截图未见圆角轮廓外的黑色矩形。窗口元数据不能证明动画中每个渲染像素无黑边，仍不宣称逐帧视觉验收或 `80ms` 中途反向连续 10 次通过。

# v0.1.3 build 31 可观测性与隐私验收

## 范围

- App：`0.1.3 (31)`，安装路径 `/Applications/顶屿.app`
- 本轮继续以汽水音乐为主适配，不启动其他音频来源，不使用 Computer Use，不发送全局媒体键，不新增媒体轮询。
- 目标是让日常日志能区分汽水切歌延迟所在阶段，并确保本地状态探针不会把用户路径或媒体内容输出到终端。

## 实现结果

- `DailyUsageAnalyzer` 日报 schema 从 4 升至 5，新增 `qishuiTrackTransitions`：总过渡数、deferred 数、首个候选、原子完整、UI 发布计数和 P50/P95。
- 日报额外统计未完成过渡、原子完整时缺封面和 UI 发布时缺封面；未完成过渡会进入 `anomalies`，并使样本覆盖标记为 `partial`。
- `QishuiStateProbe` 的根路径显示为 `~` 相对路径；文件变化只输出目录类别、不可逆 `fileToken`、文件类型和大小；JSON 只输出安全键标签、候选字段类别、字段类型和队列完整性计数。
- 未改变汽水 MediaRemote PID 定向、语义 AX 控制、来源仲裁或切歌原子发布门禁。

## M5 结论

此前 20 次主动汽水下一首门禁记录：控制 `20/20` 接受，完整收敛 `19/20`，首个可信完整包 P50 `635ms`、P95 `645ms`，另有 1 次封面未解决。QueueCache 的 27/27 条静态歌曲记录拥有完整字段，但当前没有可靠 `currentPlayableKey`，切歌期间相关缓存文件也没有实时变化，因此不能作为当前播放源。

build 31 已把剩余延迟证据接入日报，但没有找到更早且同时绑定汽水 PID 与完整曲目身份的公开直接源。`500ms` P0 门槛仍未通过；继续保持原子发布，禁止用新歌名配旧歌手、专辑、时长或封面制造假快照。下一阶段先收集日常日志，再依据 `qishuiTrackTransitions` 的真实越线情况排期。

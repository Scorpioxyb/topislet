# v0.1.2 辅助功能授权恢复与汽水三键验收

日期：2026-08-30

## 问题

顶屿仍能通过汽水专属状态流读取歌曲、播放状态、进度和封面，但 macOS 将安装版顶屿的辅助功能授权显示为关闭，导致三枚汽水控制按钮被禁用，用户点击没有动作。

## 修复

- 汽水和网易云是依赖辅助功能语义控件的来源；权限失效时控制按钮保留可点击恢复入口。
- 点击任一不可用控制时触发 `AXIsProcessTrustedWithOptions`，未授权则打开 macOS“隐私与安全性 - 辅助功能”页面。
- 每 `0.5s` 的主循环同步检查 `AXIsProcessTrusted()`，权限恢复后不要求重启顶屿即可更新控制状态。
- Apple Music 等不依赖该权限的来源不显示辅助功能恢复入口。
- 未授权时不发送控制、不使用全局媒体键、不激活汽水窗口。

## 安装版实机验证

复现时安装版 `/Applications/顶屿.app` 的控制诊断为：

```text
controlAvailability=accessibilityRequired
allowsControl=false
reason=顶屿需要辅助功能权限才能控制汽水音乐。
```

系统设置中确认“顶屿”辅助功能开关为 `off`。用户开启当前安装版顶屿授权后，安装版状态恢复为：

```text
controlAvailability=available
allowsControl=true
reason=nil
```

当前汽水播放来源为 `com.soda.music`，主进程 PID `1219`，汽水 PID `530`。来源读取保持正常，未切换前台 App。

| 操作 | 结果 | 关键证据 |
| --- | --- | --- |
| 播放 / 暂停 | 播放切换为暂停，约 1 秒后时间线保持冻结 | `semanticQishuiControlSent=true`；暂停态 `elapsedTime` 不推进 |
| 播放 / 暂停 | 暂停恢复为播放 | `semanticQishuiControlSent=true`；播放态继续推进 |
| 下一首 | 切换到下一首并在约 1 秒内收敛完整曲目 | `semanticQishuiControlSent=true`；新曲封面随后补齐 |
| 上一首 | 返回上一首并收敛完整曲目与封面 | `semanticQishuiControlSent=true` |

下一首 / 上一首的控制命令在约 `220ms` 的 CLI 即时回读中可能仍看到汽水的混合过渡包；应用主线不会直接发布该包，等待完整身份、时长与封面门控后再更新岛内 UI。约 `1s` 后的专属状态读取已确认完整新曲。

汽水窗口未被激活或弹出，其他前台媒体未被控制；本轮未使用全局媒体键、OCR 或 Computer Use。

## 结论

“辅助功能授权失效导致汽水按钮无响应”已修复并验收。权限恢复后仍需保留现有 P0 的三来源交叉切换、90 次汽水控制和窗口关闭 / 恢复门禁，不因本轮汽水三键通过而提前关闭这些独立项目。

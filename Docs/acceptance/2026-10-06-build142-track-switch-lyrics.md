# Build 142：切歌歌词加载与暂停跳转

## 确认的原因

1. 原实现无已核验歌词缓存，切回上一首仍重新执行搜索和详情两次请求。
2. 空结果固定等待 30 秒重试；现在从请求完成后 3 秒开始，随后 6、12、24、30 秒有界退避。空结果不是纯音乐的证据。
3. 实时切歌信号原本未立即调度歌词任务；现在刷新播放源后即启动。
4. 合唱歌曲在 MediaRemote 中使用逗号分隔，在 AX 与歌词源中使用斜线分隔。原实现一方面无法匹配搜索歌手，另一方面在两种身份字符串间切换，取消正在加载的请求。

## 修改

- 最多 24 首的会话内 LRU 缓存，只存成功核验的非空时间轴。键包含原始歌名、歌手和精确时长；不同录音时长不复用。关闭网络歌词会清空缓存，不写磁盘。
- 完整歌手名单比较支持上述分隔符差异；单歌手名字如 AC/DC 不凭斜线拆解。歌名和时长校验不放宽。
- 有有效汽水进程绑定的 MediaRemote 播放身份时，歌词任务统一使用该身份，AX 仅作补充。
- 取消请求在搜索、详情及解析阶段检查取消状态，已失效结果不进入展示。
- 暂停跳转后进行有界回读；仅确认同曲、同进程仍正在播放且未有更新的顶屿控制或跳转操作时，定向执行汽水 AX 暂停。更换来源、曲目或控制代数时终止。未知或缓存状态不盲目切换。

## 验证证据

- 缓存复用、LRU 淘汰、空结果不缓存、首次重试、暂停恢复门禁、多歌手匹配共新增 5 项测试；缺少实现时先失败。
- 完整 Swift 测试：312 项通过；git diff --check 通过。
- 最终安装：0.1.3 build 142；Release 40 段校验及签名通过。
- Computer Use 在中间 build 140 实测 Dopamine -> Direct With It -> Dopamine，日志确认 origin=cache，歌词继续显示。
- build 140 实测暂停后跳转 60%，日志 seek_pause_preservation outcome=sent；随后按钮保持播放、时间保持约 1:55。最终 build 142 保留同一恢复实现。
- 最终 build 142 实机 Direct With It / Swimming Paul, Beaux Neptune 成功显示时间轴歌词，主进程日志 timed_lyrics_ready origin=network latency_ms=1662。
- 独立源查询返回该合唱歌曲 79 行、445 个词时间段。原失败并非歌词源没有歌词。

## 边界

- 1662 ms 是本次网络查询时间，不是用户点击到第一帧歌词的全链路延迟，也不是普遍性能保证。
- 缓存只改善再次播放，不消除新歌的网络请求；冷启动仍需联网验证。
- 暂停恢复不是原子操作，汽水 seek 后可能短暂播放再暂停。尚未证明无声、无感保持，未进行声音回环测量。
- 最终版本没有完成快速连续切歌、用户在汽水端同时操作、断网恢复、多桌面/全屏及长时间播放的全组合测试，不标为全面稳定。
- 本轮没有推送代码或发布 GitHub Release。
